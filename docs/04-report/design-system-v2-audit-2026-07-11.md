# 바스타임 디자인 시스템 V2 감사

날짜: 2026-07-11

## 감사 범위

- 메인 `/`
- 온천 결과 `/onsen/results`
- 온천 상세 `/onsen/kusatsu-gozanoyu`
- 방법론 `/onsen/methodology`
- 로그인 `/auth/login`
- 온천여권 `/passport`
- 아카이브 탐색 `/explore`
- `DESIGN.md`, `apps/web/app/globals.css`, 공통 `Shell`

데스크톱 1280 x 900, 모바일 390 x 844에서 실제 렌더링과 주요 상호작용을 확인했다. 모든 대상 화면에서 가로 넘침과 브라우저 콘솔 오류는 없었다.

## 결론

현재 바스타임은 기능적으로 안정적이고 개별 화면의 완성도도 낮지 않다. 문제는 디자인 품질 자체보다 **세 가지 서로 다른 제품 언어가 동시에 존재한다는 것**이다.

1. 방법론의 사진 중심 편집형 아카이브
2. 온천 검색·결과·상세의 정보 도구
3. 로그인·온천여권·일반 아카이브의 기존 콘텐츠 서비스

방법론 페이지가 앞으로의 품질 기준점이다. 다만 이 화면의 큰 타이포그래피와 스크롤 연출을 모든 페이지에 복제하면 검색기의 효율이 떨어진다. V2는 방법론의 사진, 타이포그래피, 여백 감각을 공통 브랜드 언어로 추출하고 검색·상세에는 더 조밀한 도구형 문법으로 번역해야 한다.

이번 리디자인은 단순한 메인 교체가 아니라 공통 셸, 이미지 정책, 타입 역할, 상태 표현을 다시 잠그는 작업이어야 한다.

## 우선순위별 발견 사항

### P0. 화면마다 브랜드가 달라진다

- 메인은 어두운 웰니스 사진과 굵은 고딕 제목을 사용한다.
- 방법론은 실제 온천 풍경, 명조 제목, 긴 편집형 호흡을 사용한다.
- 탐색은 전형적인 콘텐츠 카드 그리드이고 로그인·온천여권은 장식이 거의 없는 유틸리티 화면이다.
- 같은 로고와 틸 색상을 제외하면 화면 사이의 공통 서명이 약하다.

**결정:** 방법론의 `Quiet Onsen Atlas`를 상위 브랜드 언어로 채택한다. 검색 결과와 폼은 그 언어의 조밀한 변형이어야 한다.

### 이미지 상태에 대한 전제

- 현재 숙소·시설 사진은 아고다 어필리에이트 승인 후 채워질 예정이다.
- 메인 판정 카드, 결과 카드, 상세의 `사진 준비 중`은 최종 디자인 상태가 아니라 임시 운영 상태다.
- 따라서 리디자인은 플레이스홀더를 중심으로 geometry를 축소하지 않고, 실제 숙소·탕 이미지가 들어온 완성 상태를 기준으로 판단한다.

이 문제는 [2026-07-07 온천 홈·상세 감사](./product-design-audit-onsen-home-detail-2026-07-07/audit.md)에서도 지적됐지만, 데이터가 222곳으로 늘어난 현재도 핵심 구조가 남아 있다.

**결정:** 메인과 상세의 미디어 우선순위는 유지한다. 시안 단계에서는 기존 지역 사진을 제휴 이미지의 프록시로 사용한다. 플레이스홀더는 별도의 임시 상태로만 설계하고 전체 디자인 방향을 결정하는 근거로 사용하지 않는다.

### P1. 상세 첫 화면은 제휴 이미지 적용 후 다시 판단한다

- 넓은 이미지 슬롯은 실제 숙소·탕 사진이 들어오면 장소 선택에 필요한 정보가 된다.
- 현재 상태만 보고 미디어를 축소하면 제휴 이미지 적용 후 다시 구조를 되돌릴 가능성이 크다.
- 다만 데스크톱 자체 리뷰 패널과 핵심 판정의 무게 관계는 이미지 유무와 별개로 다시 조정할 필요가 있다.

**결정:** 상세는 `미디어 + 정체성 + 핵심 판정`을 한 첫 화면 안에서 함께 읽히게 한다. 제휴 이미지 적용 전에는 미디어 크기 자체를 최적화 대상으로 삼지 않는다.

### P1. 디자인 토큰과 실제 CSS의 계약이 어긋난다

현재 측정값:

| 항목 | 현재 상태 |
| --- | ---: |
| `DESIGN.md` | 1,000줄 이상 |
| 전역 CSS | 9,707줄 |
| CSS raw hex 사용 | 43회, 29색 |
| px 기반 `font-size` | 194회 |
| px 기반 `border-radius` | 35회 |
| `:has()` 선택자 | 31회 |
| transition 선언 | 32개 |

- 최신 토큰 계약과 과거 컴포넌트 규칙이 한 문서에 누적되어 우선순위가 모호하다.
- 카드 최대 반경 8px 규칙과 `--bt-radius-lg: 16px` 사용이 충돌한다.
- 모션은 `transform`, `opacity`, `filter`로 제한한다고 적혀 있지만 배경색, 경계선, 그림자 전환이 넓게 사용된다.
- 페이지 변형이 공통 컴포넌트 API보다 `:has()`와 경로별 CSS 덮어쓰기에 의존한다.

**결정:** `DESIGN.md` V2는 분위기, 색, 타입, 공간, 컴포넌트, 모션, 깊이의 7개 계약으로 축소한다. 과거 IA와 장문의 설명은 별도 문서로 이동한다. CSS는 foundation, shell, onsen, archive, auth 단위로 분리한다.

### P1. 공통 헤더가 경로별 예외로 동작한다

- 투명 메인 헤더, 검색 헤더, 일반 헤더, 인증 셸이 서로 다른 규칙을 사용한다.
- 모바일 방법론은 브랜드 대신 뒤로가기와 비어 보이는 검색 필드가 첫 줄을 차지한다.
- 방법론처럼 읽기 중심인 화면에도 결과 페이지와 같은 검색 헤더가 붙는다.

**결정:** 셸은 세 종류로 고정한다.

1. `immersive`: 메인과 이미지 히어로용 투명 헤더
2. `utility`: 결과·상세·여권·탐색용 고정 헤더
3. `minimal`: 로그인과 법적 문서용 최소 셸

방법론 모바일은 검색 입력을 제거하고 뒤로가기, 작은 워드마크, 계정 액션만 사용한다.

### P1. 모바일 메인 첫 화면이 과밀하다

- 짧은 높이 안에 워드마크, 제목, 통계 블록, 방법론 링크, 검색창이 모두 들어간다.
- 통계 블록이 반투명 카드처럼 보여 히어로 카피와 검색 사이에 또 하나의 주인공이 생긴다.
- 첫 카드가 큰 플레이스홀더라 검색 이후의 가치가 약해진다.

**결정:** 히어로에는 이름, 한 문장, 검색만 남긴다. 검증 수치는 히어로 아래의 얇은 evidence strip으로 분리한다.

### P1. 결과 화면은 기능은 좋지만 시각 우선순위가 분산된다

- 필터 분류와 URL 상태는 잘 정리되어 있고 모바일 확장 패널도 기능적으로 안정적이다.
- 데스크톱 제목은 좁은 열에서 `222개`가 별도 줄로 떨어지고, 오른쪽 통계가 동일한 시각 무게를 가진다.
- 이미지가 없는 카드에서도 미디어 영역이 크게 유지된다.
- 공식 확인, 유형, 직수 배지, 일본어 이름, 근거 수, 사실 행이 한 카드에 동시에 경쟁한다.

**결정:** 결과 카드는 `이름 + 한 줄 판정 + 핵심 사실 2개 + 근거 수`를 기본 골격으로 삼는다. 이미지 유무에 따라 card geometry가 달라져야 한다. 배지는 한 줄에 최대 두 종류만 표시한다.

### P2. 접근성과 모션 규칙을 정리할 필요가 있다

- 모바일 헤더 일부 컨트롤이 32~40px로, 권장 터치 영역 44px보다 작다.
- 12~13px 텍스트가 메타, 필터, 설명에 넓게 사용된다.
- 방법론의 reveal 콘텐츠는 JavaScript가 실행되기 전 기본적으로 숨겨진다.
- `prefers-reduced-motion` 처리는 있으나 페이지별 모션 구현 방식은 통일되지 않았다.

**결정:** 터치 컨트롤 최소 44px, 본문성 텍스트 최소 14px를 기준으로 한다. reveal 콘텐츠는 기본 표시하고 JavaScript가 활성화된 경우에만 초기 숨김 상태를 적용한다.

## 유지할 자산

- 방법론 페이지의 사진 중심 편집 리듬과 명조 제목
- 히노키 틸을 선택·확인 상태에 사용하는 방식
- Phosphor 아이콘 체계
- 모바일 검색 시트의 정보 구조
- 결과 필터의 공식 사실과 후기 신호 분리 원칙
- 지역별 사진 탐색과 재고 카운트
- 로그인 화면의 최소한의 구성
- 온천여권의 비게임화 원칙

## 폐기하거나 교체할 패턴

- 메인의 같은 크기 판정 카드 4개
- 경로와 하위 DOM을 감지해 셸을 바꾸는 `:has()` 중심 규칙
- 카드마다 반복되는 그림자와 hover 상승
- 따뜻한 베이지와 틸만으로 화면 전체를 채우는 단조로운 팔레트
- 화면마다 새로 정의되는 제목 크기, 카드 반경, 상태색
- 정보가 다른데도 같은 geometry를 강제하는 숙소·시설 카드

## V2 권장 방향

### 브랜드 서명

**Quiet Onsen Atlas**

실제 장소 사진, 낮은 목소리의 판정문, 정확한 숫자, 얇은 선을 핵심 서명으로 사용한다. 장식적 일본풍이나 호텔 스파의 금색 고급감은 사용하지 않는다.

### 색

- 밝은 중성 캔버스를 기본으로 한다.
- 히노키 틸은 선택과 확인에만 사용한다.
- 미네랄 블루는 링크와 정보 상태에 사용한다.
- 철빛 적갈색은 주의와 수질 색 정보에 제한한다.
- 유황 회색은 중립 보조면에 사용한다.

### 타입

- 명조: 메인, 방법론, 장소명처럼 브랜드 인상을 만드는 제목
- 고딕: 검색, 필터, 판정, 본문, 폼
- 데이터 숫자: 판독 수와 재고 카운트에만 사용

### 형태와 깊이

- 반경은 0, 4, 8, pill 네 단계로 제한한다.
- 페이지 섹션을 카드로 감싸지 않는다.
- 기본 깊이는 선과 면 차이로 만들고, 모달과 팝오버만 그림자를 사용한다.

### 모션

- 이미지 hover 확대
- 제목 색 변화
- 짧은 opacity/transform reveal
- 검색 시트와 팝오버 전환

레이아웃 크기, 그림자, 경계선 색은 애니메이션하지 않는다.

## 실행 순서

1. `DESIGN.md` V2와 공통 토큰을 확정한다.
2. 공통 셸 세 종류를 구현한다.
3. 메인을 실제 온천 중심으로 리디자인한다.
4. 제휴 이미지가 적용된 상세 첫 화면의 미디어와 판정 균형을 재검증한다.
5. 결과 카드와 필터 hierarchy를 정리한다.
6. 온천여권, 탐색, 로그인을 같은 시스템으로 이관한다.
7. 390, 768, 1280px에서 상태별 시각 QA를 진행한다.

## 메인 시안에 적용할 첫 결정

- 첫 화면 배경은 실제 온천 장소 사진을 사용한다.
- H1, 한 줄 설명, 검색을 첫 화면의 세 요소로 제한한다.
- 숫자 근거는 히어로 아래 evidence strip으로 이동한다.
- 첫 판정은 큰 lead item 하나로 보여주고 나머지는 작은 목록으로 보조한다.
- 사진 없는 판정은 이미지 카드를 만들지 않는다.
- 지역 탐색은 현재 사진 자산을 유지하되 큰 이미지와 작은 인덱스를 섞는다.
- 방법론과 온천여권 진입은 설명 카드가 아니라 본문 흐름 안의 명확한 링크로 둔다.
