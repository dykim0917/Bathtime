## Executive Readout

이번 QA의 결론은 “콘텐츠의 재료는 좋지만, 사용자의 상황을 받아서 오늘의 행동으로 처방하는 첫 30초가 약하다”이다.

Bathtime은 이미 일반 사우나/목욕탕 DB 서비스와 다른 강점을 갖고 있다. 장문 콘텐츠는 근거와 루틴 연결이 있고, 루틴 페이지는 `샤워 7분`, `족욕 10분`, `입욕 15분`처럼 실행 단서를 명확히 준다. 하지만 핵심 페르소나가 홈이나 검색에서 들어왔을 때는 이 강점이 결과 상단에 바로 드러나지 않는다. 현재 검색 결과는 “좋은 콘텐츠 카드 목록”에 가깝고, 사용자는 “그래서 지금 뭘 하면 되지?”라는 질문을 한 번 더 해결해야 한다.

가장 큰 제품 결정은 검색/상황 결과 상단을 콘텐츠 목록이 아니라 `상황형 처방 블록`으로 바꾸는 것이다.

우선 고칠 것:

1. `욕조 없는 집`, `수면 전`, `퇴근 후` 결과 상단에 루틴/도구/콘텐츠를 묶은 처방형 블록을 둔다.
2. 검색 결과 정렬에서 상황 적합도를 아이템 최신성보다 우선한다.
3. `/app`, `/saved`, `/auth/login`은 “웹에서 발견한 콘텐츠가 앱 의식으로 이어지는 그림”을 더 구체화한다.
4. 제보 폼은 현재 신뢰 기준은 좋지만, `왜 좋은 바스타임인지`를 쓰게 만드는 질문을 더 전면에 둔다.
5. 로그인 화면은 개인정보 민감 사용자를 위해 `저장되는 것 / 저장되지 않는 것 / 비로그인 가능 범위`를 짧게 보여준다.

## Test Execution Method

이번 재실행은 화면이 열리는지만 보지 않았다. 각 TC마다 `expectedText`, `mustNotSee`, `targetAction`, `scoreHints`를 두고 아래 증거를 수집했다.

- 첫 진입 화면의 viewport text
- 상황 카드/검색 결과 첫 화면
- 결과 첫 카드 4개
- 상세 진입 후 heading, CTA, target action 노출 여부
- 금지 문구 노출 여부
- page error, console warning/error
- 케이스/variant/step별 screenshot

단, 로그인 상태 보관함과 실제 배포 앱 설치/열기 경로는 이번 로컬 테스트에서 검증하지 못했다. 이 두 항목은 PASS로 처리하지 않고 TC-05, TC-08의 막힌 지점으로 남겼다.

## TC-01. 욕조 없는 원룸 거주자

### 요약 판정

- 결과: PARTIAL
- 발견 점수: 3
- 이해 점수: 4
- 실행 가능성: 3
- 신뢰 점수: 4
- 전환 가능성: 3
- 이탈 위험: 중간

### 실제 경로

1. mobile/desktop 홈 진입
2. `욕조 없는 집` 상황 카드 확인
3. `/explore?query=욕조 없음` 도착
4. iOS app shell에서 Maestro로 홈 문구 assert 후 `욕조 없는 집` tap 통과

### 사용자가 본 첫 의미 있는 단서

- 홈: `욕조 없는 집 - 샤워와 족욕으로 가능한 홈케어를 찾습니다.`
- 결과 첫 카드: `필터 샤워헤드, 바꾸기 전에 먼저 확인할 것들`
- 그 다음 카드: `기분이 가라앉은 날, 샤워를 작은 전환점으로 쓰는 법`, `잠들기 90분 전, 따뜻한 샤워가 몸에 하는 일`

### 막힌 지점

첫 결과가 `필터 샤워헤드`인 점이 가장 큰 마찰이다. 욕조 없는 사용자의 핵심 질문은 “욕조 없이 오늘 뭘 할 수 있나?”인데, 첫 카드는 “무엇을 살까?”에 가깝다. 두 번째부터는 5분/6분 샤워 루틴이 보이지만, 첫 인상이 아이템 구매 쪽으로 기울어져 있다.

### 제품 인사이트

`욕조 없음`은 Bathtime의 가장 강한 진입점이다. 이 사용자는 사우나 DB보다 “내 집 조건에서도 가능한 의식”을 원한다. 따라서 결과 상단은 콘텐츠 카드가 아니라 `샤워 5분`, `족욕 10분`, `작은 욕실 도구`를 한 묶음으로 보여줘야 한다.

### 바로 고칠 것

- `욕조 없음` 검색/상황 결과 상단에 `오늘 가능한 선택지` 블록 추가
- 첫 결과를 필터 샤워헤드가 아니라 5분 샤워, 10분 족욕, 욕실 의자 중 하나로 재정렬
- 카드 메타에 `오늘 바로 가능`, `욕조 없음`, `5분/10분`을 더 강하게 노출

### 후속 실험

- A안: 기존 카드 목록
- B안: `오늘 가능한 3가지` 처방 블록
- 목표: 첫 콘텐츠 클릭률, 루틴 CTA 클릭률, 앱 CTA 클릭률 비교

### 막힌 지점

수면 전 맥락 자체는 잘 잡힌다. 문제는 입문자가 “오늘 밤 당장 할 것”보다 조명/족욕기 같은 아이템 판단을 먼저 만난다는 점이다. 수면 전 사용자는 휴대폰으로 들어왔고 에너지가 낮다. 첫 화면에서 “6분 샤워”가 바로 보여야 실행 가능성이 4 이상으로 올라간다.

### 제품 인사이트

수면 전 콘텐츠의 신뢰 톤은 좋다. `수면 보장`처럼 과장하지 않고 조명, 온감, 식는 시간으로 설명한다. 다만 검색 결과의 순서가 쇼핑 탐색처럼 보이면 이 신뢰가 실행으로 이어지지 않는다.

### 바로 고칠 것

- `수면 전` 결과 상단에 `오늘 처음이면 이것만: 6분 샤워` 블록 추가
- `하지 않는 게 좋은 것`을 함께 노출: 너무 뜨거운 물, 자기 직전 긴 샤워 등
- 아이템 카드는 루틴 뒤에 배치

### 후속 실험

- 수면 전 검색 결과에서 첫 화면에 `6분`, `하지 않는 것`, `저장/앱에서 실행` 3요소를 노출했을 때 콘텐츠 상세 진입률과 앱 CTA 클릭률 측정

### 제품 인사이트

이 케이스는 핵심 TOP 3 중 가장 위험하다. Bathtime이 “오늘의 상태에 맞는 바스타임”이라고 말하면서, 실제 검색 결과에서는 상태보다 아이템 유형이 우선되는 순간 신뢰가 약해진다.

### 바로 고칠 것

- `퇴근 후` 검색 결과 상단에 `퇴근 후 15분 회복` 처방 블록 추가
- 하위 선택지: `서서 샤워하기 힘든 날`, `오래 서 있던 날`, `야근 후 바로 잘 준비`
- 첫 화면에 실행 시간과 난이도 노출: `5분`, `10분`, `앉아서 가능`, `욕조 없음`

### 후속 실험

- `퇴근 후` 검색어 전용 ranking rule 추가 전후로 첫 카드 클릭률과 이탈률 비교

## TC-04. 욕실 아이템 구매 전 판단 사용자

### 요약 판정

- 결과: PARTIAL
- 발견 점수: 2
- 이해 점수: 4
- 실행 가능성: 3
- 신뢰 점수: 4
- 전환 가능성: 3
- 이탈 위험: 중간

### 실제 경로

1. mobile web `/explore?query=아이템` 진입
2. 아이템 검색 결과 확인
3. 첫 콘텐츠 `필터 샤워헤드, 바꾸기 전에 먼저 확인할 것들` 확인

### 사용자가 본 첫 의미 있는 단서

- `필터 샤워헤드를 제품 추천이 아니라, 매일 샤워 루틴에 실제로 맞는지 확인하는 체크리스트로 정리합니다.`
- `1만~5만 원대 중심 · 교체 필터 별도`

### 막힌 지점

톤은 좋다. “제품 추천”이 아니라 “체크리스트”라고 명시하고 가격/교체 필터도 보여준다. 문제는 `아이템` 검색 결과가 필터 샤워헤드 하나만 강하게 보인다는 점이다. 사용자는 아이템 카테고리의 폭, 즉 조명/의자/족욕볼/수건/샤워헤드의 지형을 먼저 보고 싶다.

### 제품 인사이트

아이템 영역은 광고/제휴처럼 보이면 신뢰가 바로 깨진다. 현재 개별 콘텐츠의 문체는 신뢰를 만든다. 따라서 개선 포인트는 본문이 아니라 탐색 구조다.

### 바로 고칠 것

- `아이템` 검색 결과 상단에 유형 카드 추가: `앉아서 쉬기`, `수면 전 조도`, `족욕 도구`, `샤워 수질/수압`, `마무리 도구`
- 제품 후보보다 `구매 전 체크리스트`를 먼저 노출
- 검색어 `족욕`, `욕실 의자`, `조명`에 대한 대표 콘텐츠를 함께 노출

### 후속 실험

- 아이템 결과를 단일 리스트형 vs 유형 지도형으로 비교

2. 비로그인 저장 안내 확인
3. Google 로그인 CTA 확인

### 사용자가 본 첫 의미 있는 단서

### 막힌 지점

비로그인 화면은 “저장 목록을 보려면 로그인”까지는 설명한다. 하지만 사용자의 핵심 질문은 “저장한 글이 앱에서 실제 행동으로 이어지나?”이다. 현재 문구는 보관 기능 중심이고, 저장 콘텐츠가 앱의 타이머/의식으로 바뀌는 장면이 부족하다.

로그인 상태 보관함은 이번 자동화에서 검증하지 못했다. 따라서 기대 결과 중 `저장 콘텐츠 카드 확인`, `연결된 의식 CTA 확인`은 미검증이다.

### 제품 인사이트

보관함은 단순 북마크가 되면 서비스 차이가 약해진다. Bathtime의 보관함은 `저장한 콘텐츠 → 오늘 실행할 의식`의 출발점이어야 한다.

### 바로 고칠 것

- 비로그인 보관함 상단에 예시 흐름 추가: `잠들기 90분 전 글 저장 → 앱에서 6분 샤워 타이머 실행`
- 로그인 CTA 주변 문구를 `저장 목록 확인`이 아니라 `저장한 의식을 이어서 실행`으로 조정
- 로그인 상태 QA를 위한 seeded account 또는 mocked auth 상태 마련

### 후속 실험

- saved 페이지에서 예시 브릿지 카드가 있을 때 Google CTA 클릭률과 `/app` CTA 클릭률 비교

### 제품 인사이트

### 바로 고칠 것

- `왜 좋았나요?`를 단일 textarea placeholder가 아니라 별도 질문으로 분리
- 예시 추가: `조용함`, `물 온도`, `초심자에게 편한 점`, `혼자 가기 좋은 이유`, `씻고 난 뒤의 기분`
- 사진 권리 안내는 현재처럼 유지

### 후속 실험

- 기존 폼 vs 경험 질문형 폼의 제출 완료율과 제보 품질 비교

- 배포 앱 기준 QA 케이스 별도 작성: Universal Link, App Store 미설치, 설치됨, 로그인 상태별

## Cross-Case Insights

### 1. 검색 결과가 “상황 이해”보다 “카드 매칭”으로 동작한다.

`욕조 없음`, `수면 전`, `퇴근 후` 모두 결과가 없는 것은 아니다. 오히려 관련 콘텐츠는 있다. 문제는 사용자가 가장 먼저 봐야 할 콘텐츠가 앞에 오지 않는다는 점이다. 핵심 페르소나 TOP 3의 실패는 콘텐츠 부족보다 정렬/패키징 문제다.

### 2. 루틴 페이지는 좋은데, 핵심 진입점에서 잘 호출되지 않는다.

`/routines`는 `샤워 7분`, `족욕 10분`, `수면 전 샤워 6분`처럼 실행 가능성이 높다. 하지만 검색 결과에서는 이 루틴 구조가 상단에 보이지 않는다. 검색 결과와 루틴 프리셋을 연결해야 한다.

### 3. 아이템 콘텐츠는 신뢰를 만들 수 있지만 탐색 폭이 좁다.

필터 샤워헤드 콘텐츠는 “추천이 아니라 체크리스트”라는 점에서 방향이 좋다. 다만 `아이템` 검색 결과가 한두 개로 좁게 보이면 서비스가 작아 보인다. 아이템은 개별 제품보다 유형 지도를 먼저 보여주는 편이 낫다.

### 4. 앱 전환은 아직 기능 설명이다.

`웹에서는 콘텐츠를 읽고, 앱에서는 타이머와 보관함`이라는 설명은 이해되지만 행동 욕구는 약하다. 앱 전환의 핵심은 저장 콘텐츠가 타이머/의식/기록으로 바뀌는 순간을 보여주는 것이다.

### 5. 제보와 장문 콘텐츠는 상대적으로 준비가 좋다.

제보 화면은 출처, 공개 전 확인, 사진 권리 안내가 있어 신뢰가 높다. 장문 콘텐츠는 근거와 루틴 CTA가 연결되어 있어 브랜드 차별점이 분명하다. 즉, 제품의 뼈대는 있다. 홈/탐색/전환 레이어가 이 뼈대를 더 잘 꺼내야 한다.

## Product Priority

### P0. 핵심 상황 결과 상단의 처방형 블록

대상: `욕조 없는 집`, `수면 전`, `퇴근 후`

각 결과 상단에 아래 구조를 둔다.

- 오늘 바로 할 수 있는 루틴 1개
- 조건에 맞는 도구/아이템 1개
- 읽어볼 가이드 1개
- 앱에서 실행 CTA 1개
