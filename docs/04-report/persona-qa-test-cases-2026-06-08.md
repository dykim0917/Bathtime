# Bathtime Persona QA Test Cases

작성일: 2026-06-08

목적: 페르소나별로 화면이 열리는지만 확인하지 않고, 사용자가 자기 상황을 이해받고 다음 행동을 할 이유를 찾는지 검증한다.

## 리포트 판정 기준

좋은 페르소나 QA 리포트는 아래 질문에 답해야 한다.

1. 이 사람은 어떤 생활 상황에서 들어왔는가?
2. 첫 화면에서 자기 문제와 연결되는 단서를 발견했는가?
3. 콘텐츠, 저장, 앱 실행, 제보 중 다음 행동이 자연스러운가?
4. 신뢰를 잃는 지점은 어디인가?
5. 이 페르소나를 위해 제품을 고친다면 무엇을 먼저 해야 하는가?

## 공통 측정 항목

각 케이스는 아래 항목을 기록한다.

| 항목 | 기록 방식 |
|---|---|
| 발견 점수 | 1~5. 원하는 맥락의 콘텐츠를 찾기 쉬운가 |
| 이해 점수 | 1~5. 바스타임이 무엇을 해주는 서비스인지 이해되는가 |
| 실행 가능성 | 1~5. 오늘 바로 할 수 있는 행동이 보이는가 |
| 신뢰 점수 | 1~5. 정보 출처, 톤, 화면 구성이 믿을 만한가 |
| 전환 가능성 | 1~5. 저장, 앱 이동, 제보, 콘텐츠 열람으로 이어질 가능성 |
| 이탈 위험 | 낮음 / 중간 / 높음 |
| 막힌 지점 | 사용자가 멈추거나 헷갈릴 만한 순간 |
| 제품 결정 | 이 케이스가 제안하는 가장 중요한 개선 |

## 성공 기준

페르소나 QA 통과 기준:

- 핵심 페르소나 TOP 3는 발견 점수 4 이상이어야 한다.
- 핵심 페르소나 TOP 3는 실행 가능성 4 이상이어야 한다.
- 앱 전환 케이스는 전환 가능성 3 이상이어야 한다.
- 제보 케이스는 신뢰 점수 4 이상이어야 한다.
- 어떤 케이스든 이탈 위험이 높음이면 원인을 제품 결정으로 남긴다.

## 핵심 페르소나

초기 제품 판단에서 가장 중요한 페르소나는 아래 5개다.

1. 욕조 없는 집에 사는 사용자
2. 수면 전 짧은 루틴을 찾는 사용자
3. 퇴근 후 몸을 풀고 싶은 사용자
4. 욕실 아이템을 사기 전에 판단 기준을 찾는 사용자
5. 저장한 콘텐츠를 앱 의식으로 이어가려는 사용자

나머지 페르소나는 보조 검증으로 둔다.

## TC-01. 욕조 없는 원룸 거주자

### 사용자 상황

원룸에 살고 욕조가 없다. 몸은 피곤하지만 입욕은 불가능하다. 샤워나 족욕만으로 회복감을 만들 수 있는지 알고 싶다.

### 핵심 질문

"욕조가 없어도 오늘 바로 할 수 있는 바스타임이 있나?"

### 시작 조건

- 비로그인
- mobile web, desktop web, iOS app shell 각각 1회
- 첫 진입 경로는 홈

### 경로

1. 홈 진입
2. `욕조 없는 집` 상황 카드 선택
3. 첫 번째 콘텐츠 제목과 설명 확인
4. 콘텐츠 상세 진입
5. 저장 버튼 또는 앱 CTA 확인

### 관찰 포인트

- 홈 첫 화면에서 `욕조 없는 집`이 충분히 눈에 띄는가
- 결과 상단 콘텐츠가 실제로 욕조 없는 상황과 맞는가
- 콘텐츠 상세에서 "오늘 할 수 있는 것"이 30초 안에 보이는가
- 샤워, 족욕, 작은 욕실 도구가 같은 맥락으로 연결되는가
- 앱으로 이어지는 이유가 기능 설명이 아니라 의식 실행으로 느껴지는가

### 실패 신호

- 필터 샤워헤드처럼 욕조 없음과 약한 콘텐츠가 첫 결과로 나온다.
- 사용자가 "그래서 뭘 하면 되지?" 상태로 남는다.
- 앱 CTA가 저장 이후 흐름과 연결되지 않는다.

### 기대 결과

- 발견 점수 4 이상
- 실행 가능성 4 이상
- 첫 결과는 샤워 루틴, 족욕, 작은 욕실 도구 중 하나여야 한다.

### 제품 결정 후보

욕조 없는 집 결과 상단에는 일반 콘텐츠 목록보다 `오늘 가능한 7분 샤워 루틴`, `10분 족욕`, `작은 욕실 도구`를 묶은 처방형 블록을 먼저 둔다.

## TC-02. 수면 전 짧은 루틴 입문자

### 사용자 상황

잠들기 전 휴대폰을 보다가 들어왔다. 복잡한 설명보다 오늘 밤 바로 할 수 있는 짧은 루틴을 원한다.

### 핵심 질문

"잠들기 전에 뭘 하면 덜 부담스럽게 몸을 정리할 수 있나?"

### 시작 조건

- 비로그인
- mobile web 우선
- 홈 또는 검색 진입

### 경로

1. 홈 진입
2. `수면 전` 상황 카드 선택
3. 결과 상단 3개 콘텐츠 확인
4. `욕실 조명` 또는 `따뜻한 샤워` 콘텐츠 진입
5. 루틴 CTA 확인

### 관찰 포인트

- 결과가 제품, 콘텐츠, 루틴 중 무엇부터 보여주는가
- 입문자가 고를 수 있는 "오늘 처음이면 이것만" 단서가 있는가
- 수면 효능을 과장하지 않고 환경/습관 조정으로 설명하는가
- 앱 의식으로 이어지는 CTA가 자연스러운가

### 실패 신호

- 조명, 족욕기 같은 아이템이 먼저 보여서 쇼핑 검색처럼 느껴진다.
- 수면 보장처럼 읽히는 문구가 있다.
- 루틴 실행 시간이나 난이도가 보이지 않는다.

### 기대 결과

- 이해 점수 4 이상
- 실행 가능성 4 이상
- 신뢰 점수 4 이상

### 제품 결정 후보

수면 전 결과에는 `오늘 처음이면 이것만`, `하지 않는 게 좋은 것`, `6분 루틴`을 상단에 둔다.

## TC-03. 퇴근 후 회복을 찾는 직장인

### 사용자 상황

하루 종일 일하고 돌아왔다. 긴 콘텐츠를 읽을 에너지는 낮다. 몸을 풀 수 있는 짧은 선택지가 필요하다.

### 핵심 질문

"지금 너무 피곤한데, 씻는 시간을 회복처럼 만들 수 있나?"

### 시작 조건

- desktop web, mobile web 각각 1회
- 검색어: `퇴근 후`

### 경로

1. 홈 진입
2. 탐색 진입
3. `퇴근 후` 검색
4. 결과 첫 화면 확인
5. 첫 콘텐츠 상세 진입

### 관찰 포인트

- 검색 결과가 퇴근 후 상황을 정확히 반영하는가
- 콘텐츠 목록보다 짧은 루틴 선택지가 먼저 보이는가
- 욕실 의자, 족욕, 샤워 루틴이 "회복" 맥락으로 연결되는가
- 사용자가 클릭 전에 실행 시간과 난이도를 알 수 있는가

### 실패 신호

- 결과가 단순 콘텐츠 카드 목록처럼 보인다.
- 퇴근 후보다 수면 전, 아이템 구매 맥락이 먼저 보인다.
- 7분/10분 같은 실행 단서가 없다.

### 기대 결과

- 발견 점수 4 이상
- 실행 가능성 4 이상
- 전환 가능성 3 이상

### 제품 결정 후보

검색 결과 상단에 `퇴근 후 15분 회복`, `오래 서 있던 날`, `야근 후 샤워` 같은 상황형 묶음을 노출한다.

## TC-04. 욕실 아이템 구매 전 판단 사용자

### 사용자 상황

족욕볼, 욕실 의자, 조명, 샤워헤드 같은 물건을 사야 할지 고민한다. 추천 순위보다 자기 집에 맞는 조건을 알고 싶다.

### 핵심 질문

"이걸 사면 오래 쓸까, 아니면 귀찮아서 방치할까?"

### 시작 조건

- mobile web
- 검색어: `아이템`, `족욕`, `욕실 의자`, `조명` 중 2개 이상

### 경로

1. 탐색 진입
2. `아이템` 검색
3. 카테고리 필터 `욕실 아이템` 선택
4. 아이템 콘텐츠 상세 진입
5. 제품 후보 영역 확인

### 관찰 포인트

- 아이템 카테고리 폭이 보이는가
- 제품 추천 TOP처럼 보이지 않는가
- 구매 전 체크리스트가 제품 후보보다 먼저 판단 기준을 주는가
- 실제 제품 후보가 "비교해볼 만한 후보"로 읽히는가
- 가격 기준일과 정보 상태가 보이는가

### 실패 신호

- 특정 제품 구매 유도처럼 보인다.
- 제품 이미지나 가격이 근거 없이 신뢰를 요구한다.
- 아이템 검색 결과가 한두 개로 좁게 보인다.

### 기대 결과

- 신뢰 점수 4 이상
- 이해 점수 4 이상
- 전환 가능성 3 이상

### 제품 결정 후보

아이템 탐색은 `유형 카드`, `구매 전 체크리스트`, `비교 후보 카드`의 구조를 유지하고, 검색 결과에서는 아이템 유형의 폭을 먼저 보여준다.

## TC-05. 저장한 콘텐츠를 앱 의식으로 이어가려는 사용자

### 사용자 상황

웹에서 콘텐츠를 보다가 저장했다. 앱에서 실제 루틴을 실행할 수 있다면 넘어갈 의향이 있다.

### 핵심 질문

"내가 저장한 글이 앱에서 실제 행동으로 이어지나?"

### 시작 조건

- 로그인 상태와 비로그인 상태 각각 테스트
- mobile web, iOS app shell 각각 1회

### 경로 A. 비로그인

1. `/saved` 진입
2. 로그인 안내 확인
3. Google 로그인 CTA 확인

### 경로 B. 로그인

1. 앱 shell에서 보관함 탭 선택
2. 저장된 콘텐츠 목록 확인
3. 콘텐츠 상세 진입
4. 연결된 의식 CTA 확인

### 관찰 포인트

- 비로그인 상태에서 왜 로그인해야 하는지 납득되는가
- 로그인 후 이전 비로그인 화면에 갇히지 않는가
- 저장 콘텐츠가 앱 의식과 연결된다는 그림이 보이는가
- 보관함이 단순 북마크 목록이 아니라 다음 행동의 출발점처럼 보이는가

### 실패 신호

- 로그인 후에도 비로그인 보관함 화면이 남는다.
- 보관함이 단순 저장 목록처럼 보인다.
- 앱 CTA가 "앱으로 이동" 이상의 이유를 주지 못한다.

### 기대 결과

- 로그인 후 보관함 화면에 `다시 보고 싶은 바스타임 기록`이 보인다.
- `보관함 설정` 또는 저장 콘텐츠 카드가 보인다.
- 전환 가능성 4 이상

### 제품 결정 후보

보관함 상단에 `저장한 콘텐츠 → 앱에서 실행할 의식`의 연결 예시를 짧게 보여준다.

## TC-06. 좋은 목욕 공간을 제보하려는 사용자

### 사용자 상황

좋은 사우나, 숙소 대욕장, 목욕 공간을 알고 있다. 하지만 무엇을 어떻게 제보해야 하는지 확신이 없다.

### 핵심 질문

"여기 좋은데, 바스타임에 어떤 정보를 남기면 도움이 될까?"

### 시작 조건

- 비로그인, 로그인 각각 1회
- desktop web 우선

### 경로

1. 홈에서 `좋은 공간 제보` 선택
2. `/submit` 진입
3. 제보 유형 선택
4. 장소명, 주소, 설명 입력
5. 제출 직전 상태 확인

### 관찰 포인트

- 제보 목적이 장소 DB 추가가 아니라 좋은 바스타임 단서 수집으로 보이는가
- "왜 좋은지"를 쓰게 만드는 질문이 있는가
- 사진 권리, 정보 출처, 공개 여부 안내가 있는가
- 비로그인 사용자가 왜 로그인해야 하는지 납득하는가

### 실패 신호

- 폼이 일반 문의/게시판처럼 보인다.
- 장소명과 주소만 중요한 것처럼 보인다.
- 사진 업로드나 출처 안내가 불명확하다.

### 기대 결과

- 신뢰 점수 4 이상
- 전환 가능성 3 이상
- 사용자가 남길 내용의 예시를 이해한다.

### 제품 결정 후보

제보 폼에 `좋은 제보 예시`, `사진/출처 안내`, `왜 좋은 바스타임인지` 질문을 전면 배치한다.

## TC-07. 긴 콘텐츠를 읽는 태블릿 사용자

### 사용자 상황

잠들기 전 태블릿으로 긴 글을 읽는다. 블로그 글이 아니라 신뢰 가능한 가이드처럼 읽히길 기대한다.

### 핵심 질문

"이 글은 그냥 감성 글인가, 아니면 내 루틴을 바꿀 근거가 있나?"

### 시작 조건

- tablet viewport
- 콘텐츠 상세 직접 진입

### 경로

1. `/content/care-sleep-warm-shower-90` 진입
2. 히어로, 한 줄 판단, 본문 구조 확인
3. 근거/자료 영역 확인
4. 연결된 의식 CTA 확인

### 관찰 포인트

- 첫 화면이 이미지에만 잠기지 않는가
- 제목, 한 줄 판단, 본문 첫 섹션이 자연스럽게 이어지는가
- 장문 콘텐츠의 중간 이탈을 줄이는 구조가 있는가
- 루틴 CTA가 글의 결론처럼 보이는가

### 실패 신호

- 히어로 이미지가 너무 커서 핵심 문장이 늦게 보인다.
- 요약과 본문이 반복된다.
- 루틴 CTA가 광고처럼 보인다.

### 기대 결과

- 이해 점수 4 이상
- 신뢰 점수 4 이상
- 전환 가능성 3 이상

### 제품 결정 후보

상세 페이지는 히어로 아래에 바로 `한 줄 판단`, `오늘 할 수 있는 것`, `연결된 의식`의 흐름을 유지한다.

## TC-08. 앱 설치/열기 전환 사용자

### 사용자 상황

웹에서 콘텐츠를 봤다. 앱에서 실행 기능이 있다면 열어볼 수 있지만, 설치/열기 이유가 약하면 이탈한다.

### 핵심 질문

"앱을 열면 웹에서 못 하는 뭘 할 수 있나?"

### 시작 조건

- mobile web
- `/app` 직접 진입과 콘텐츠 상세 CTA 진입 각각 테스트

### 경로

1. `/app` 진입
2. 앱 역할 설명 확인
3. 앱 열기/설치 CTA 확인
4. 콘텐츠 상세에서 앱 CTA 진입

### 관찰 포인트

- 웹과 앱의 역할 차이가 선명한가
- 앱에서 가능한 의식 실행이 구체적으로 보이는가
- 저장한 콘텐츠와 앱 루틴이 연결되는가
- 로컬 dev-client 경로가 아닌 실제 사용자 경로를 검증할 수 있는가

### 실패 신호

- 앱 CTA가 "앱에서 이어가기" 이상의 정보를 주지 않는다.
- 실제 앱 설치/열기 경로가 QA에서 검증되지 않는다.
- 앱을 열어도 같은 웹 화면처럼 느껴진다.

### 기대 결과

- 이해 점수 4 이상
- 전환 가능성 3 이상
- 실제 배포 앱 기준 QA 계획이 남는다.

### 제품 결정 후보

`/app` 페이지에 `웹에서 발견 → 저장 → 앱에서 의식 실행`을 3단계로 시각화한다.

## TC-09. 개인정보에 민감한 로그인 사용자

### 사용자 상황

저장 기능은 쓰고 싶지만 Google 로그인과 데이터 저장 범위가 신경 쓰인다.

### 핵심 질문

"로그인하면 무엇이 저장되고, 무엇은 저장되지 않나?"

### 시작 조건

- desktop web, mobile web
- `/auth/login` 직접 진입
- `/saved`에서 로그인 유도 진입

### 경로

1. `/saved` 진입
2. 로그인 안내 확인
3. `/auth/login` 진입
4. Google CTA 주변 설명 확인

### 관찰 포인트

- 로그인 이유가 기능 중심이 아니라 사용자 이득으로 설명되는가
- 저장되는 정보 범위가 짧고 명확한가
- 비로그인으로 가능한 범위가 보이는가
- 개인정보처리방침으로 가는 길이 있는가

### 실패 신호

- "Google로 계속하기"만 있고 데이터 설명이 없다.
- 개인정보 민감 사용자가 바로 이탈할 만한 공백이 있다.
- 저장/제보/의식 기록의 데이터 범위가 섞여 보인다.

### 기대 결과

- 신뢰 점수 4 이상
- 전환 가능성 3 이상

### 제품 결정 후보

로그인 화면에 `저장되는 것`, `저장되지 않는 것`, `언제든 로그아웃 가능`의 3줄 요약을 추가한다.

## TC-10. 콘텐츠가 너무 블로그처럼 보이는지 의심하는 사용자

### 사용자 상황

사용자는 목욕/샤워 콘텐츠를 많이 봤고, 흔한 블로그성 글에는 피로감이 있다. 바스타임이 다른 이유를 빠르게 판단한다.

### 핵심 질문

"이건 그냥 감성 콘텐츠인가, 아니면 실제 선택과 행동을 돕는 아카이브인가?"

### 시작 조건

- desktop web
- 홈, 탐색, 아이템 상세, 홈케어 상세 각각 확인

### 경로

1. 홈 진입
2. 새로 정리한 기록 확인
3. 아이템 콘텐츠 상세 진입
4. 홈케어 콘텐츠 상세 진입
5. 앱 루틴 CTA 확인

### 관찰 포인트

- 카드 메타 정보가 판단 기준을 제공하는가
- 본문 구조가 감상문이 아니라 의식/조건/체크리스트로 보이는가
- 제품 후보가 추천 랭킹처럼 보이지 않는가
- 루틴 CTA가 콘텐츠의 실천 결과처럼 보이는가

### 실패 신호

- 제목과 본문이 일반 블로그 글처럼 느껴진다.
- "좋다", "추천" 같은 단정 문구가 많다.
- 실제 행동으로 이어지는 구조가 약하다.

### 기대 결과

- 이해 점수 4 이상
- 신뢰 점수 4 이상

### 제품 결정 후보

모든 콘텐츠 상세는 `한 줄 판단`, `이런 사람에게 맞음`, `사기/하기 전 볼 것`, `아쉬운 점`, `연결된 의식` 구조를 유지한다.

## 자동화 메모

- Playwright는 DOM 에러, console 에러, 주요 텍스트, URL, screenshot을 수집한다.
- Maestro는 iOS 앱 shell에서 하단 탭, 상황 카드, 보관함 세션 브릿지, 앱 루틴 진입을 검증한다.
- 자동화는 점수 판정을 대신하지 않는다. 점수는 screenshot과 evidence를 읽고 사람이 판정한다.
- 다음 단계에서는 각 케이스별로 `expectedText`, `mustNotSee`, `targetAction`, `scoreHints`를 JSON으로 추가하면 리포트 자동 생성 품질이 올라간다.
