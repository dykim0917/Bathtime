# 리추얼 로그 오버레이 UX 설계

## 1. 화면의 역할

리추얼 로그 화면은 사용자가 만든 욕실 속 쉼의 장면을 더 저장하고 싶게 만드는 편집 화면이다.

이 화면은 루틴 실행을 유도하지 않는다. 사용자가 이미 만든 장면을 기록하고 표현하게 한다.

## 2. 기본 플로우

1. 사진 선택
2. 무드 선택
3. 환경 선택
4. 태그 선택
5. 문구 자동 생성
6. 템플릿 선택
7. 저장 또는 공유

## 3. 정보 구조

오버레이에 들어가는 정보는 짧고 시각적이어야 한다.

- photo
- title
- ritualLine
- moodLabel
- environmentLabel
- productTags
- date/time
- hashtags
- brand mark

P0에서는 단계형 `ritualSteps`, `duration`, `sound`, `safetyNote`를 넣지 않는다.

## 4. 템플릿 방향

### minimal

사진을 가장 크게 두고, 좌하단에 작은 제목과 태그만 얹는다.

### spa

호텔 스파 메뉴 카드처럼 차분한 타이포와 얇은 라인을 쓴다.

### magazine

제목을 크게 두고, 무드와 태그를 에디토리얼 캡션처럼 배치한다.

### soft

일기처럼 부드러운 문장과 날짜를 강조한다.

## 5. 문구 톤

문구는 처방이 아니라 캡션이어야 한다.

- “해야 한다”보다 “이렇게 남겼다”
- 건강 효과보다 장면의 질감
- 상세한 순서보다 한 줄의 분위기
- 제품 구매 유도보다 사용자의 취향 해석

예시:

- 오늘은 우디한 향과 낮은 조명으로 속도를 조금 늦췄다.
- 비 오는 밤처럼 차분하게, 따뜻한 물과 허브 향만 남긴 시간.
- 욕조 없는 밤에도 작은 트레이 하나면 홈스파가 된다.
- 운동 후의 열기를 산뜻한 시트러스 향으로 정리한 저녁.

## 6. 저장용과 공유용 차이

### 앱 내 저장용

- 원본 사진과 오버레이 데이터를 함께 보관
- 나중에 템플릿과 문구를 다시 바꿀 수 있어야 함
- 날짜, 태그, 환경으로 필터링 가능해야 함

### SNS 공유용

- 하나의 이미지로 export
- 텍스트가 작아도 읽히도록 대비 확보
- 인스타 스토리/피드 비율을 우선 고려
- 해시태그는 복사 가능한 텍스트로도 제공

## 7. P0 QA 기준

- 사진 없이 시작할 수 없어야 한다.
- 오버레이 텍스트가 밝은 사진과 어두운 사진 모두에서 읽혀야 한다.
- 긴 태그 조합에서도 레이아웃이 무너지지 않아야 한다.
- 저장/공유 후 사용자가 방금 만든 이미지를 확인할 수 있어야 한다.
- 웹에서는 공유가 제한될 수 있으므로 저장 또는 다운로드 fallback이 있어야 한다.
