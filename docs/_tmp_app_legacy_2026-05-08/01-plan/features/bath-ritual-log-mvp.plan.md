# 바스타임 MVP 재정의: 리추얼 로그 앱

## 1. 한 줄 정의

바스타임 MVP는 리추얼을 추천하고 실행시키는 앱이 아니라, 사용자가 직접 세팅한 욕실 속 쉼의 장면을 리추얼 로그로 기록하고 공유하게 해주는 앱이다.

## 2. 피벗의 중심 행동

기존 방향은 상태 선택, 루틴 추천, 타이머 실행, 완료 기록으로 이어졌다. 이 구조는 기존 샤워/목욕 루틴 앱의 연장선에 가깝다.

새 MVP의 중심 행동은 다음과 같다.

> 사진을 고른다 → 무드와 태그를 얹는다 → 바스타임다운 오버레이를 만든다 → 저장하거나 공유한다

사용자는 앱에게 “오늘 뭘 해야 하지?”를 묻는 것이 아니라, “오늘 내가 만든 쉼의 장면을 더 근사하게 남기고 싶다”는 동기로 들어온다.

## 3. 새 제품 정의

### MVP 제품 정의

바스타임은 내가 세팅한 욕실/홈스파 사진 위에 무드, 향, 제품 태그, 짧은 리추얼 문구를 얹어 저장하고 공유하는 리추얼 로그 앱입니다.

### MVP 핵심 약속

오늘의 욕실 속 쉼의 장면을, 저장하고 공유하고 싶은 리추얼 로그 카드로 만든다.

### 장기 방향

바스타임은 욕실에서의 쉼을 기록, 공유, 발견, 구매로 연결하는 바스 리추얼 플랫폼으로 확장한다.

## 4. 하지 않을 것

P0에서는 아래 기능을 제거한다.

- 상태 기반 추천
- 건강/회복 목적 기반 추천
- 단계형 루틴 상세
- 타이머 실행
- 사운드 실행
- 완료 후 기분 선택
- 의료적 효능 또는 컨디션 처방 문구

이 기능들은 기존 앱 자산으로는 유효하지만, 새 MVP의 중심 행동을 흐린다.

## 5. P0 범위

### 1. 사진 촬영 또는 업로드

사용자는 욕실, 욕조 트레이, 입욕제, 향초, 바디케어 선반, 족욕 세팅, 수건/가운 등 자신이 연출한 쉼의 장면을 촬영하거나 업로드한다.

초기 검증에서는 이미지 품질 보정이나 자동 인식보다, 사진을 고르고 로그를 만드는 흐름 자체가 중요하다.

### 2. 무드 선택

사용자는 사진에 얹을 분위기를 고른다.

예시:

- 조용한 밤
- 가벼운 리셋
- 깊은 휴식
- 호텔 스파
- 비 오는 욕실
- 운동 후 정리

무드는 추천 조건이 아니라 표현 레이어다.

### 3. 환경 선택

환경은 실행 가능성 판정이 아니라 사진의 장면 분류다.

- 샤워
- 족욕
- 욕조
- 홈스파

### 4. 향/제품 태그 선택

사용자는 사진에 등장하거나 오늘 사용한 제품의 느낌을 태그로 고른다.

- 우디
- 허브
- 플로럴
- 시트러스
- 머스크
- 무향
- 촉촉함
- 산뜻함
- 입욕제
- 바디워시
- 바디오일
- 향초
- 스크럽
- 수건
- 트레이

태그는 추천 엔진 입력값이 아니라, 로그의 취향 표식이다.

### 5. 짧은 리추얼 문구 생성

앱은 선택된 무드, 환경, 태그를 바탕으로 사진 위에 얹을 짧은 문구를 만든다.

문구는 실행 지시가 아니라 장면을 해석하는 한 줄이어야 한다.

나쁜 예:

> 1분간 어깨를 풀고 3분간 따뜻한 물로 샤워하세요.

좋은 예:

> 우디한 향과 낮은 조명으로 오늘의 속도를 조금 늦춘 밤.

### 6. 오버레이 템플릿 적용

사용자는 사진 위에 텍스트, 태그, 날짜, 로고가 얹힌 템플릿을 고른다.

초기 템플릿:

- minimal: 작은 타이포와 여백 중심
- spa: 호텔 스파 느낌의 차분한 레이아웃
- magazine: 제목과 태그가 강한 에디토리얼형
- soft: 부드러운 톤의 기록형

### 7. 저장 / SNS 공유

사용자는 완성된 이미지를 저장하거나 공유한다.

P0에서는 내부 커뮤니티 피드를 만들지 않는다. 저장률과 공유 시도율을 먼저 본다.

## 6. 핵심 타입 초안

```ts
export type RitualLogEnvironment = 'shower' | 'footbath' | 'bathtub' | 'home_spa';

export type RitualLogTemplate = 'minimal' | 'spa' | 'magazine' | 'soft';

export interface RitualLogOverlay {
  id: string;
  photoUri: string;
  title: string;
  moodLabel: string;
  environmentLabel: string;
  productTags: string[];
  ritualLine: string;
  guideLine?: string;
  timeLabel?: string;
  templateStyle: RitualLogTemplate;
  hashtags: string[];
  createdAt: string;
}
```

## 7. 성공 지표

| 지표 | 의미 |
| --- | --- |
| 사진 업로드/촬영 시작률 | 사용자가 장면 기록에 진입하는가 |
| 오버레이 생성 완료율 | 결과물을 만드는 데 부담이 없는가 |
| 템플릿 변경률 | 꾸미는 재미가 있는가 |
| 저장률 | 결과물이 보관 가치가 있는가 |
| 공유 시도율 | SNS 확산 가능성이 있는가 |
| 재방문/재생성률 | 반복 로그 가능성이 있는가 |

## 8. 최상위 검증 질문

> 사용자는 자신의 욕실/홈스파 사진을 바스타임 템플릿으로 더 근사하게 만들고 싶어 하는가?

이 질문에 Yes가 나오면 커뮤니티, 제품 태그 기반 피드, 제품 큐레이션, 제휴 링크로 확장할 수 있다. No가 나오면 추천 엔진이나 타이머를 붙여도 피벗의 핵심 가설은 살아나지 않는다.

## 9. 개발 계획으로 내려갈 때의 원칙

- 기존 `BathRecommendation`, 타이머, 완료 화면은 P0에서 재사용하지 않는다.
- 첫 진입점은 홈 화면의 “리추얼 로그 만들기” CTA다.
- 첫 구현은 이미지 선택, 메타 선택, 오버레이 미리보기, 저장/공유에만 집중한다.
- 카메라 권한, 이미지 저장 권한, 공유 API는 플랫폼별 차이를 명확히 분리한다.
- 사진 보정, 자동 제품 인식, AI 문구 생성은 P1 이후로 둔다.
