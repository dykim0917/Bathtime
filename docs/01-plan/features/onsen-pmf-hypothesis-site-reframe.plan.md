# 바스타임 온천 PMF 가설 기반 사이트 개편 계획

작성일: 2026-07-13
상태: Draft
적용 범위: 온천 홈, 검색 결과, 상세, 데이터 노출 계약, 웹 분석 계측

## 0. 문서 목적

이 문서는 현재 바스타임이 PMF를 달성했다는 전제에서 출발하지 않습니다. 아직 실제 사용자 수요의 증거는 없으며, 지금까지 확인된 근거는 창업자의 반복된 일본 온천 탐색·이용 경험입니다.

따라서 이번 개편의 목적은 새로운 모델을 더 만드는 것이 아니라 다음 가설을 **실제 사용자 행동으로 검증할 수 있는 사이트 구조**로 바꾸는 것입니다.

> 일본 온천에 관심이 있는 한국인 여행자는 OTA의 `대욕장 있음` 같은 이진 정보만으로는 실제 목욕 경험의 깊이와 이용 방법을 판단하기 어렵다. 바스타임이 예산, 탕 구성, 프라이빗 이용 방식, 운영 조건을 한 흐름에서 설명하면 숙소 예약과 시설 방문 결정을 더 잘 내릴 수 있다.

이번 계획은 전면적인 시각 디자인 교체가 아닙니다. 이미 완성된 디자인 시스템, 검색, 지도, 판정, 후기, 온천여권을 재사용하고 제품의 우선순위와 정보 구조를 다시 배열합니다.

## 1. 발견된 사용자 문제

### 1.1 실제 탐색 흐름

창업자가 료칸을 선택할 때 사용한 흐름은 다음과 같습니다.

1. 한국 커뮤니티에서 가격대와 가성비 후보를 찾습니다.
2. OTA에서 가격, 가이세키, 객실탕, 노천탕 여부를 비교합니다.
3. OTA에서 알 수 없는 정보는 숙소명으로 일본 공식 사이트를 다시 검색합니다.
4. 실제 공간과 이용 장면을 확인하기 위해 유튜브를 추가로 검색합니다.
5. 대절탕이 예약제인지, 선착순인지, 비어 있는지는 어떻게 확인하는지 끝까지 알아봅니다.

경쟁 서비스는 다른 온천 검색기가 아니라 `커뮤니티 + OTA + 일본 공식 사이트 + 유튜브`를 이어 붙인 현재 방식입니다.

### 1.2 OTA의 정보 손실

`대욕장 있음`은 다음 경험을 구분하지 못합니다.

- 온탕과 냉탕 정도만 있는 호텔 부속 대욕장
- 노천탕, 항아리탕, 전기탕, 제트탕, 탄산탕 등이 있는 대형 온천시설
- 객실에서 독립적으로 이용하는 온천탕
- 예약제·현장 선착순·빈 탕 확인형 대절탕

사용자가 알고 싶은 것은 시설의 존재 여부보다 다음 질문의 답입니다.

- 어떤 탕을 경험할 수 있는가?
- 누구와 함께 이용할 수 있는가?
- 예약부터 현장 입장까지 어떻게 이용하는가?
- 여행 일정과 예산 안에 넣을 수 있는가?
- 이 정보는 공식 확인인지, 후기에서 반복된 경험인지?

### 1.3 시설 DB가 필요한 이유

시설은 일반 일본 여행자의 첫 번째 목적지가 아닐 가능성이 큽니다. 창업자의 첫 일본 온천 경험도 주유패스 무료 혜택이 진입 장벽을 낮췄기 때문에 발생했습니다.

그럼에도 시설 DB는 다음 이유로 유지합니다.

- 숙소 부속 대욕장과 전문 온천시설의 경험 차이를 설명합니다.
- 이미 온천을 좋아하는 여행자에게 반복 탐색 이유를 줍니다.
- 당일 이용, 심야 이용, 밤샘, 숙박, 암반욕 같은 OTA 취약 정보를 제공합니다.
- 장기적으로 패스, 할인, 티켓, 여행 동선과 연결할 수 있습니다.

시설은 초기 상업적 진입점이 아니라 바스타임의 경험 차별화와 확장층입니다.

## 2. 제품 가설

### 2.1 한 줄 정의

> 바스타임은 일본 온천에 관심 있는 한국인 여행자가 예산 안에서 목욕 경험이 좋은 숙소와 시설을 찾고, 실제 이용 방법을 이해해 예약·방문을 결정하도록 돕는 온천 중심 여행 의사결정 서비스입니다.

### 2.2 사용자에게 주는 약속

> `대욕장 있음`을 넘어, 어떤 탕을 누구와 어떻게 이용할 수 있는지 정리합니다.

### 2.3 초기 사용자

주 타깃:

- 일본 자유여행을 준비 중인 한국인
- 온천을 여행 선택 기준으로 이미 고려하는 사람
- 한 번 이상의 좋은 온천 경험이 있거나, 료칸·객실탕·대절탕에 명확한 관심이 있는 사람
- 숙소나 시설을 고르기 위해 한국어 후기, OTA, 일본 공식 사이트를 오가는 사람

보조 타깃:

- 첫 일본 료칸 여행에서 둘이 함께 이용할 탕을 찾는 커플
- 도쿄, 오사카, 후쿠오카 등 기존 여행 일정에 온천시설을 추가하려는 사람
- 호텔 대욕장과 전문 온천시설의 차이를 모르지만 더 좋은 목욕 경험에는 관심이 있는 사람

초기 비타깃:

- 온천에 관심이 전혀 없고 가격·무료 혜택 외에는 방문 동기가 없는 일반 여행자
- 성분표나 원천 방식만을 목적으로 탐색하는 극소수 전문가층
- 커뮤니티 활동과 여권 수집 자체가 주목적인 사용자

## 3. 제품 우선순위

사이트의 정보는 다음 다섯 층으로 정리합니다.

1. **발견**: 어떤 목욕 경험을 할 수 있는지 보여줍니다.
2. **비교**: 예산, 탕 구성, 프라이빗 이용, 숙박·당일 조건으로 후보를 좁힙니다.
3. **이용**: 예약, 선착순, 수건, 시간 제한, 심야요금 등 실제 행동을 설명합니다.
4. **근거**: 공식 사실과 후기 집계를 분리해 판단을 뒷받침합니다.
5. **기록**: 방문 후 온천여권과 회원 후기로 경험을 축적합니다.

`판정 모델`은 제품명이거나 첫 화면의 주인공이 아닙니다. 발견·비교·이용 정보를 신뢰하게 만드는 근거층으로 유지합니다.

## 4. 검증할 세 가지 진입 가설

각 진입점은 별도의 `entry_intent`로 추적합니다.

| 코드 | 사용자 문장 | 핵심 대상 | 일차 행동 |
| --- | --- | --- | --- |
| `stay_private` | 둘이 같은 탕에 들어가고 싶다 | 객실탕·대절탕 숙소 | 예약 후보 확인 |
| `stay_bath_depth` | 숙소의 대욕장 때문에 예약하고 싶다 | 탕 구성이 강한 숙소 | 경험 비교 후 예약 확인 |
| `city_facility` | 여행 중 두세 시간을 온천에서 보내고 싶다 | 당일·심야·숙박 가능 시설 | 이용 조건과 동선 확인 |

`stay_private`와 `stay_bath_depth`는 상업적 주 진입점입니다. `city_facility`는 차별화와 장기 재방문 가능성을 검증하는 보조 진입점입니다.

## 5. 사이트 정보 구조

### 5.1 전체 흐름

```text
홈의 욕구 진입점 또는 검색
  -> 의도와 위치가 반영된 결과
  -> 목욕 경험과 이용 조건이 보이는 카드
  -> 상세의 경험 프로필·이용 방법·가격
  -> 예약/공식/지도 행동
  -> 저장·공유
  -> 방문 후 온천여권·후기
```

### 5.2 홈

유지할 것:

- 감성적 히어로와 `이번 여행엔, 온천이 목적이어도 좋으니까.` 방향
- 헤더 검색
- 사진 중심 발견 경험
- 지역별 온천, 온천수 방식, 방법론 진입

바꿀 것:

1. 히어로 바로 아래에 세 가지 `entry_intent`를 노출합니다.
2. 현재의 `조용한 탕`, `둘만 쓰는 객실탕`, `풍경 좋은 노천탕` 섹션은 세 진입 가설과 연결되도록 재편합니다.
3. 각 섹션 CTA는 결과 URL에 `intent`를 포함합니다.
4. 카드 문구는 장소 소개보다 `왜 이 목욕 경험을 선택할 만한지`를 먼저 말합니다.
5. 비로그인 사용자에게 온천여권을 핵심 획득 가치처럼 앞세우지 않습니다.
6. 로그인 사용자의 온천여권 밴드는 유지하되 첫 탐색 흐름을 가로막지 않습니다.

권장 섹션 문장:

- `둘이 같은 탕에 들어가고 싶을 때.`
- `숙소보다 대욕장이 기억에 남았으면 할 때.`
- `여행 중 두세 시간을 온천에서 보내고 싶을 때.`

### 5.3 검색 결과

결과 화면은 데이터 목록이 아니라 비교 도구가 되어야 합니다.

유형 언어:

- `숙박하며 이용` — 온천 숙소
- `여행 중 방문` — 당일·심야·복합 온천시설

필터 우선순위:

1. 위치 검색
2. 이용 형태: 숙박 / 일정 중 방문
3. 함께 이용: 객실 내 프라이빗탕 / 대절탕 / 가족탕
4. 목욕 경험: 노천탕 / 탕 구성 다양 / 암반욕 / 사우나 / 특별 체험
5. 운영 조건: 당일 / 심야 / 밤샘·숙박 / 예약 필요
6. 가격: 제휴 가격 또는 공식 입장료가 준비된 항목만
7. 온천수 방식·성분: 고급 필터로 유지

결과 카드의 기본 골격:

1. 이름과 위치
2. 한 줄 목욕 경험 요약
3. 가격 또는 가격 확인 CTA
4. 핵심 결정 사실 2개
5. 온천수 방식 배지
6. 회원 후기 수

숙소와 시설은 같은 geometry를 강제하지 않습니다.

숙소 카드 예:

```text
시라하마 야나기야
객실탕과 바다 쪽 대욕장을 함께 비교할 수 있는 숙소
객실 내 프라이빗탕 · 대욕장 노천탕
가격 확인
```

시설 카드 예:

```text
류센지노유 소카야쓰카점
공식 안내 기준 탕 15종, 암반욕과 심야 이용 가능
06:00-02:00 · 주말 1,100엔
지도에서 보기
```

### 5.4 상세

상세의 첫 질문은 `바스타임이 무엇을 판정했는가`가 아니라 `내 여행에 맞는가`입니다.

권장 순서:

1. 장소명, 위치, 갤러리, 가격/예약/지도 CTA
2. 목욕 경험 한 줄 요약
3. `이런 여행에 맞음`
4. `여기서 할 수 있는 목욕`
5. `실제 이용 방법`
6. `여행 일정에 넣기`
7. 온천수 방식과 공식 사실
8. 후기에서 반복된 경험
9. 회원 후기와 온천여권
10. 출처와 확인일

`여기서 할 수 있는 목욕`은 점수 대신 확인된 경험 프로필을 보여줍니다.

```text
탕 구성 15종 공식 확인
노천탕 있음
암반욕 별도 요금
대절탕 현장 선착순
심야 02:00까지
```

`실제 이용 방법`은 사용자의 행동 순서로 씁니다.

```text
프런트에서 대절탕 이용 여부를 확인합니다.
예약 없이 비어 있는 탕을 이용합니다.
객실에서 빈 탕 여부를 확인하는 장치는 없습니다.
이용 시간 제한은 공식 안내에서 확인되지 않았습니다.
```

시설 상세 필수 항목:

- 당일 이용 가능 여부
- 운영 시간과 마지막 입장
- 입장료와 별도 요금
- 수건 포함·대여·구매
- 암반욕·사우나 추가 요금
- 심야 할증
- 밤샘·숙박 방식
- 휴게 공간과 재입장
- 문신·연령·혼욕 제한
- 역·주차·셔틀 접근

숙소 상세 필수 항목:

- 객실탕 적용 객실 범위
- 대절탕 예약 방식
- 빈 탕 확인 방식
- 이용 시간과 비용
- 커플·가족 동반 이용 가능 여부
- 대욕장 탕 구성과 노천탕
- 당일입욕 제공 여부
- 숙박 가격과 예약 가능 여부

### 5.5 온천여권과 회원 후기

온천여권은 획득 퍼널이 아니라 방문 이후의 유지 퍼널입니다.

- 홈 비로그인 핵심 섹션에서는 우선순위를 낮춥니다.
- 상세에서 방문 후 기록하는 자연스러운 위치를 유지합니다.
- 회원 후기는 공식 이용 사실과 분리합니다.
- 초기 PMF 판단에서 회원가입 수를 주 지표로 사용하지 않습니다.
- 실제 방문 후 후기가 쌓이면 시설 정보 신선도와 경험 프로필을 보조합니다.

## 6. 데이터 노출 계약

### 6.1 기존 데이터 우선 사용

새 점수 모델이나 신규 테이블부터 만들지 않습니다. 먼저 아래 기존 자산을 사용자 결정 사실로 변환합니다.

- `onsen_*_official_filter_facts`
- `onsen_facilities.official_profile`
- `onsen_facilities.lodging_available`
- `onsen_*_water_facts`
- `onsen_*_review_signals`
- `onsen_verdicts`

이미 존재하는 주요 공식 필터:

- `day_use`, `lodging`, `morning_bath`, `late_night`, `adult_day_use_price`
- `open_air_bath`, `private_bath`, `family_bath`, `mixed_bathing`
- `jet_bath`, `sleeping_bath`, `sauna`, `water_bath`, `stone_sauna`
- `rest_area`, `meal_service`, `tattoo_allowed`, `english_support`
- `station_walk_10m`, `parking`, `shuttle`

이미 존재하는 주요 후기 신호:

- `bath_variety`
- `family_private_bath_experience`
- `reservation_or_queue_confusion`
- `price_payment_value`
- `tourist_expectation_gap`
- `eligibility_or_use_scope`
- `operation_volatility`

### 6.2 우선 정규화할 결정 사실

기존 `official_profile.official_facts`의 자유문장을 다음 구조로 정규화합니다.

| 필드 | 예시 | 신선도 |
| --- | --- | --- |
| `bath_count` | 15 | 180일 |
| `signature_baths` | 항아리탕, 탄산탕, 전기탕 | 180일 |
| `private_bath_reservation_method` | 사전 예약 / 현장 예약 / 선착순 / 빈 탕 이용 | 90일 |
| `vacancy_check_method` | 프런트 / 객실 표시 / 현장 확인 | 90일 |
| `private_bath_time_limit_minutes` | 45 | 90일 |
| `towel_policy` | 포함 / 대여 / 구매 / 지참 | 30일 |
| `opening_hours` | 06:00-02:00 | 30일 |
| `last_entry_at` | 01:30 | 30일 |
| `adult_price_yen` | 1100 | 30일 |
| `late_night_surcharge_yen` | 1800 | 30일 |
| `overnight_mode` | 객실 / 캡슐 / 리클라이너 / 불가 | 30일 |
| `reentry_policy` | 가능 / 불가 / 조건부 | 30일 |

구현 전 데이터 감사에서 기존 `filter_value`로 표현 가능한 항목은 신규 컬럼을 만들지 않습니다. 여러 화면과 수집 파이프라인에서 반복 사용될 때만 스키마 확장을 결정합니다.

### 6.3 경험 프로필 원칙

초기에는 `목욕 경험 점수`를 만들지 않습니다.

- 점수 대신 확인된 탕 수와 대표 탕을 보여줍니다.
- 공식 사실과 후기 신호를 같은 숫자로 합치지 않습니다.
- 데이터가 없는 장소에는 추정 점수를 붙이지 않습니다.
- `탕 구성 다양` 필터는 공식 탕 수 또는 명시된 구성 기준을 통과한 곳만 노출합니다.
- 점수 모델은 사용자 행동에서 탕 구성이 실제 선택에 영향을 준다는 증거가 나온 뒤 검토합니다.

### 6.4 시험 재고

전국 재고 전체를 먼저 백필하지 않습니다. 세 진입 가설을 검증할 30곳을 우선 선정합니다.

- `stay_private`: 숙소 10곳
- `stay_bath_depth`: 숙소 10곳
- `city_facility`: 시설 10곳

초기 후보 지역은 창업자 경험과 현재 재고를 기준으로 오사카, 도쿄·요코하마, 후쿠오카, 하코네, 유후인·벳푸를 우선 검토합니다. 최종 지역은 Search Console과 외부 검색 수요 조사 후 확정합니다.

시험 모듈 노출 게이트:

- 필수 결정 사실 80% 이상
- 공식 출처 URL 존재
- 운영 정보 신선도 기준 충족
- 가격이 없으면 `가격 미확인`이 아니라 명확한 외부 확인 CTA 제공
- 이용 방식이 불명확하면 해당 사실을 장점처럼 노출하지 않음

### 7.3 핵심 지표

PMF를 페이지뷰로 판단하지 않습니다.

일차 지표:

- 숙소: `상세 -> 예약/가격 확인 클릭률`
- 시설: `상세 -> 공식/티켓/지도 행동률`
- 공통: `결과 -> 상세 클릭률`

이차 지표:

- 저장·공유율
- 같은 세션에서 두 곳 이상 상세 비교 비율
- 30일 내 온천 영역 재방문율
- 방문 후 후기 작성 완료율

초기 실험용 합성 지표:

```text
decision_action_rate =
  예약 클릭 또는 시설 행동이 발생한 고유 상세 세션
  / 결정 사실을 볼 수 있었던 고유 상세 세션
```

이 지표는 장기 North Star가 아니라 세 진입 가설을 비교하기 위한 임시 운영 지표입니다.

숙소 예약 클릭과 시설 지도 클릭은 같은 강도의 행동이 아닙니다. `action_type`별 원시 수치를 반드시 보존하고 다음처럼 intent별 일차 행동을 따로 봅니다.

- `stay_private`, `stay_bath_depth`: 제휴 예약·가격 확인 클릭
- `city_facility`: 티켓·예약 클릭을 최우선, 길찾기를 그다음, 공식 사이트 확인을 보조 행동으로 구분
- 공통: 저장·공유는 관심 신호이며 예약·방문 결정과 합산하지 않음

따라서 intent 간 `decision_action_rate` 비교는 방향성 판단에만 사용하고 서로 다른 행동을 하나의 전환 숫자로 더해 사업성을 비교하지 않습니다.

### 7.4 배포와 비교 가능성

C안은 화면만 바꾸고 기다리는 실험이 아닙니다. 세 intent가 외부에서 발견될 경로를 함께 준비합니다.

- 외부 검색 수요 조사 후 intent마다 하나의 안정적인 canonical 진입 URL을 둡니다.
- 진입 URL은 설명만 있는 마케팅 페이지가 아니라 해당 조건의 실제 재고와 결과를 바로 보여줍니다.
- 홈, 검색 유입, SNS·커뮤니티 공유 링크가 같은 `entry_intent` 계약을 사용합니다.
- `utm_source`, `utm_medium`, `utm_campaign`은 intent와 분리해 유입 경로와 제품 욕구를 혼동하지 않습니다.
- Search Console 쿼리를 세 intent와 `unknown`으로 분류합니다.
- 계측과 자연 유입 기준선이 생기기 전에는 넓은 유료 광고를 집행하지 않습니다.

유입이 부족한 상태에서 전환 0건이 나오면 제품 가설을 기각하지 않습니다. 이 경우 결과는 `distribution not validated`입니다.

### 7.5 가격·예약 데이터 게이트

숙소 선택에서 가격은 보조 정보가 아니라 첫 번째 제약입니다. 가격과 예약 가능 여부가 없는 `stay_private`, `stay_bath_depth`를 가격이 준비된 시설 intent와 직접 비교하면 숙소 가설에 불리한 실험이 됩니다.

- 아고다 등 제휴 가격 적용 전 숙소 이벤트는 `information intent`로만 해석합니다.
- 제휴 가격 적용 후 `booking intent` 코호트를 별도로 시작합니다.
- `has_price`, `price_source`, `price_checked_at`을 분석 속성에 포함합니다.
- 제휴사의 실제 예약 전환 리포트가 확보되면 클릭보다 실제 예약을 상위 지표로 사용합니다.
- 가격이 없는 상세의 `가격 확인` 클릭은 예약 완료와 같은 전환으로 해석하지 않습니다.

목표: 세 intent 중 실제 행동을 만드는 진입점을 찾습니다.

기간:

- 최소 4주
- 또는 intent별 qualified session 50건 도달 시점까지

초기 운영 게이트:

- 세 intent 합계 qualified session 150건 이상
- 전체 decision action 10건 이상
- 한 intent가 다른 intent보다 2주 연속 높은 decision action rate를 보임
- 최소 한 진입점에서 저장·공유 또는 반복 비교 행동 발생
- 비교하는 intent 사이에 가격·결정 사실 커버리지 차이가 과도하지 않음

이 숫자는 통계적 PMF 판정선이 아니라 다음 투자 우선순위를 정하기 위한 초기 운영 기준입니다. 첫 2주 기준선이 생기면 임계값을 재고정합니다.

## 9. 결과 해석 규칙

| 관찰 | 해석 | 다음 행동 |
| --- | --- | --- |

| 숙소 가격 적용 전 행동이 낮음 | 숙소 수요 실패로 판정할 수 없음 | 제휴 가격 적용 후 코호트 재측정 |
| 저장·공유는 높고 외부 행동은 낮음 | 영감 콘텐츠 가치는 있으나 결정력 약함 | 콘텐츠와 거래 퍼널 분리 판단 |
| 외부 행동은 높고 재방문은 낮음 | 반복 서비스보다 거래 유틸리티 | affiliate·SEO 사업성으로 평가 |
| 방문 후기와 여권 사용이 증가 | 유지·데이터 네트워크 가능성 | 후기·여권 투자를 재개 |

유입이 부족하면 제품 실패로 판정하지 않습니다. 유입 없이 전면 리디자인을 반복하지 않고 배포 문제로 분리합니다.

## 10. 이번 단계에서 하지 않을 일

- 전국 재고 수를 늘리는 것 자체를 목표로 삼지 않음
- 새로운 AI 판정 점수나 목욕 경험 종합 등급을 만들지 않음
- 기존 판정 데이터를 폐기하거나 전면 재수집하지 않음
- 디자인 시스템을 다시 전면 교체하지 않음
- 온천여권 게임화, 팔로우, 댓글, 커뮤니티 확장을 하지 않음
- 모바일 앱 전환을 먼저 만들지 않음
- 실제 유입 없이 전환율을 추정해 PMF라고 선언하지 않음

## 11. 의존성과 미해결 항목

### 제휴 데이터

- 아고다 승인 후 숙소 사진, 가격, 예약 CTA 적용
- 승인 전에는 공식 사이트 또는 허용된 외부 확인 경로 사용
- 제휴 가격이 없는 상태의 클릭률과 가격 적용 후 클릭률을 분리 측정

### 시장 수요 조사

- 한국어 `대절탕`, `객실탕`, `료칸 대욕장`, `일본 온천시설`, `도시별 온천` 검색 의도 조사
- 기존 OTA·블로그·커뮤니티가 어떤 질문에 답하지 못하는지 확인
- Search Console 실제 쿼리와 페이지를 세 intent로 분류

본 문서는 창업자 경험에서 도출한 가설 계획이며, 외부 검색 수요 조사는 아직 완료되지 않았습니다.

### 운영 정보 신선도

- 가격·시간·휴무·입장 규정은 30일 기준
- 대절탕 예약 방식과 이용 시간은 90일 기준
- 탕 구성은 180일 기준
- 만료 사실은 필터에서 제외하고 상세에 확인일과 함께 표시

## 12. QA 기준

기능:

- 세 intent가 홈, 결과, 상세, 외부 행동까지 유지됨
- 알 수 없는 query parameter와 값은 무시됨
- 숙소·시설 필터가 잘못 섞이지 않음
- 0건 상태에서 사용자가 다른 intent나 전체 결과로 이동 가능
- 예약/공식/지도 링크가 올바른 대상에 연결됨

데이터:

- 카드와 상세의 가격·시간·탕 구성 값이 같은 source에서 파생됨
- 공식 사실과 후기 집계가 합쳐지지 않음
- 만료된 운영 사실이 필터에 사용되지 않음
- `탕 구성 다양`이 마케팅 문구가 아니라 확인된 수치·구성에 기반함

분석:

- 이벤트 중복 없음
- 모바일·데스크톱에서 같은 event contract 사용
- 개발 트래픽과 운영 트래픽 구분
- intent 없는 자연 검색 유입은 `unknown`으로 보존
- 이벤트에 인증 이메일·닉네임 등 개인정보를 넣지 않음

화면:

- 390px, 768px, 1280px에서 가로 넘침 없음
- 결과 필터·지도·팝오버가 잘리지 않음
- 숙소·시설 카드가 각 데이터 밀도에 맞는 구조를 사용
- 사진 적용 전후에도 CTA와 핵심 결정 사실이 첫 화면에서 사라지지 않음

## 14. 첫 번째 실행 과제

다음 개발 작업은 새 모델이 아니라 아래 두 묶음으로 시작합니다.

1. 온천 퍼널 이벤트 계약과 `entry_intent` 귀속 구현
2. 세 intent별 시험 재고 10곳씩, 총 30곳의 결정 사실 커버리지 감사

이 두 작업이 끝나기 전에는 홈·결과·상세의 대규모 UI 변경을 시작하지 않습니다. 측정할 수 있고 보여줄 데이터가 준비된 뒤 같은 기준으로 세 화면을 개편합니다.
