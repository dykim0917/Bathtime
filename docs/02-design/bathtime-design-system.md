# 바스타임 디자인 시스템

## 1. 목적

바스타임 디자인 시스템은 콘텐츠, 온천 검색기, 저장, 제보, 앱 연결 화면이 같은 서비스처럼 보이게 만드는 기준이다.

새 기능을 만들 때마다 화면을 새로 꾸미지 않는다. 같은 토큰, 같은 정보 밀도, 같은 문장 톤을 사용해서 사용자가 “바스타임 안에서 움직이고 있다”고 느끼게 한다.

## 2. 참고 방향

Vercel Geist에서 가져올 것은 특정 시각 스타일보다 원칙이다.

- 정보가 먼저 읽히고 장식은 뒤로 물러난다.
- 타이포그래피로 위계를 만든 뒤 색과 선을 보조로 쓴다.
- 모든 제목을 두껍게 만들지 않는다.
- 숫자, 날짜, ID, 상태값처럼 확인해야 하는 정보는 더 정밀하게 보이게 한다.
- 인터페이스는 차분하고 예측 가능해야 한다.

바스타임은 한국어 서비스이므로 Geist Sans를 그대로 전면 적용하지 않는다. 기본 서체는 Pretendard 계열을 유지하고, 히어로와 브랜드 문장에만 필요한 만큼 명조 계열을 사용한다.

## 3. 바스타임의 시각 언어

### 핵심 인상

- 따뜻한 종이색 배경
- 흰 표면 위의 정리된 기록
- 짙은 청록색의 신뢰감
- 황동빛 보조색의 온기
- 둥글지만 과하게 귀엽지 않은 모서리
- 많은 정보를 담되 소리 지르지 않는 화면

### 피해야 할 인상

- 여행사 랜딩페이지처럼 과하게 팔아붙이는 화면
- 블로그 글처럼 본문만 길게 이어지는 화면
- 찜질방/목욕탕 광고처럼 자극적인 온열 이미지
- 모든 카드가 같은 높이와 같은 강조를 갖는 단조로운 화면
- 내부 데이터 키가 그대로 노출되는 화면

## 4. 토큰

CSS 토큰은 [globals.css](/Users/exem/DK/BathSommelier/apps/web/app/globals.css)의 `--bt-*` 변수를 기준으로 사용한다.

### 색

| 역할 | 토큰 | 용도 |
|---|---|---|
| Canvas | `--bt-color-canvas` | 페이지 전체 배경 |
| Surface | `--bt-color-surface` | 카드, 패널, 입력 영역 |
| Soft Surface | `--bt-color-surface-soft` | 보조 패널, 안내 박스 |
| Ink | `--bt-color-ink` | 제목, 핵심 문장 |
| Body | `--bt-color-body` | 본문 |
| Muted | `--bt-color-muted` | 메타 정보, 보조 설명 |
| Primary | `--bt-color-primary` | 선택 상태, 주요 액션 |
| Primary Active | `--bt-color-primary-active` | 활성 메뉴, 강한 링크 |
| Primary Soft | `--bt-color-primary-soft` | 선택된 칩, 약한 강조 배경 |
| Accent | `--bt-color-accent` | 온기, 주의, 보조 강조 |
| Border | `--bt-color-border` | 기본 선 |

### 글자

| 역할 | 토큰 | 원칙 |
|---|---|---|
| 기본 UI | `--bt-font-sans` | 네비게이션, 카드, 본문, 폼 |
| 브랜드 문장 | `--bt-font-editorial` | 홈 히어로, 소개 페이지의 짧은 선언 |
| 데이터 | `--bt-font-data` | 날짜, 가격, 온도, 시간, 코드 |

글자 굵기는 기본적으로 400, 500, 600만 사용한다. 700 이상은 로고, 선택된 메뉴, 아주 강한 수치 강조처럼 제한적으로 사용한다.

### 간격과 모서리

- 간격은 `--bt-space-*` 토큰을 사용한다.
- 카드와 패널은 `--bt-radius-md`를 기본값으로 한다.
- 버튼, 칩, 태그는 `--bt-radius-pill`을 쓸 수 있다.
- 카드 안에 또 카드처럼 보이는 구조는 피한다.

## 5. 컴포넌트 원칙

### 카드

카드는 하나의 기록 단위다. 제목, 짧은 설명, 메타 정보, 이미지가 한 번에 스캔되어야 한다.

- 기본: `bt-card`
- 클릭 가능: `bt-card bt-card-interactive`
- 썸네일은 비율을 고정한다.
- 카드 전체가 링크면 카드 전체가 클릭되어야 한다.

### 칩과 뱃지

칩은 필터나 상태 선택에 사용한다. 뱃지는 읽기 전 힌트에 사용한다.

- 선택 가능한 항목은 `bt-chip`
- 선택 상태는 `data-state="active"`
- 광고, 제휴, 확인 필요 같은 상태는 카드 제목보다 약하게 둔다.

### 데이터 패널

온천 검색기, 한눈에 보기, 가격, 운영 정보처럼 확인이 필요한 영역은 본문과 다르게 보여야 한다.

- 제목은 짧게 쓴다.
- 근거 상태를 함께 보여준다.
- 날짜가 있는 정보는 날짜를 숨기지 않는다.
- 숫자와 날짜는 `bt-data`를 사용한다.

### 안내 박스

긴 설명 대신 사용자가 다음 행동을 판단할 수 있는 문장을 넣는다.

- 기본: `bt-callout`
- 한 문단을 넘기지 않는다.
- “좋아요”, “추천해요”보다 “이런 경우에 맞아요”처럼 조건을 말한다.

## 6. 온천 검색기 적용 규칙

온천 검색기는 숙소 소개가 아니라 예약 전 확인 도구다.

### 보여줄 정보

- 객실탕에 온천수가 들어오는지
- 대욕장, 가족탕, 객실탕 중 어디가 핵심인지
- 온천수 체감이 후기에서 반복되는지
- 물 추가, 온도 조정, 순환/여과, 소독 여부가 확인되는지
- 객실 타입별 차이가 있는지
- 후기에서 반복되는 주의할 점이 있는지

### 표현 규칙

| 내부/원문 | 사용자 노출 |
|---|---|
| 源泉かけ流し | 원천 흘려보냄 |
| 加水 | 물 추가 |
| 加温 | 온도 조정 |
| 循環ろ過 | 순환/여과 |
| 消毒 | 소독 |
| 객실 노천탕 | 객실 노천탕 |
| 정보 없음 | 확인 필요 |

일본어 원문은 상세 근거에서만 보조로 병기한다. 첫 화면에서 `가케나가시` 같은 말을 먼저 내세우지 않는다.

### 상태 뱃지

- `확인됨`: 공식 안내나 반복 후기에서 확인된 정보
- `확인 필요`: 객실 타입, 시즌, 플랜에 따라 달라질 수 있는 정보
- `후기 근거`: 반복 후기에서 확인되는 체감 정보
- `주의`: 예약 전에 반드시 확인해야 하는 정보

## 7. 문장 톤

사용자는 긴 글을 읽으러 온 것이 아니라 판단을 줄이러 온다.

- “추천”보다 “맞는 경우”를 쓴다.
- “최고”, “필수”, “무조건”을 쓰지 않는다.
- “루틴”은 사용자 노출 문구에서 쓰지 않고 “의식”으로 통일한다.
- 불확실한 정보는 그럴듯하게 말하지 않고 “확인 필요”로 남긴다.
- 출처가 다른 정보는 한 문장 안에서 섞지 않는다.

## 8. 신규 화면 체크리스트

새 기능이나 페이지를 만들기 전에 아래를 확인한다.

- 이 화면은 기록, 판단, 실행 중 무엇을 돕는가?
- 첫 화면에서 사용자가 바로 이해할 한 문장이 있는가?
- 카드와 패널이 같은 토큰을 쓰는가?
- 이미지가 없어도 정보 구조가 무너지지 않는가?
- 모바일에서 첫 화면에 핵심 행동이 보이는가?
- 내부 키, 원문 용어, 조사 메모가 그대로 노출되지 않는가?
- 사용자가 다음에 누를 버튼이 하나는 분명한가?
