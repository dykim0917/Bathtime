# 바스타임: 목욕 콘텐츠 자동 보관 도구 경쟁 서비스 조사

조사일: 2026-09-21

## 조사 범위와 결론

공식 기능 소개·도움말·앱스토어 이용 후기를 읽은 데스크 리서치다. 앱을 설치해 가져오기 정확도나 한국어 지원을 직접 시험한 결과는 아니다. 기능 설명은 사업자가 제공하는 사양이며, 후기는 사용자가 스스로 보고한 경험이다. 공개된 일부 후기를 전체 이용자의 행동 비율이나 현재 버전의 결함으로 일반화하지 않는다. 연도가 표시되지 않은 후기 날짜는 원문 표시 그대로 기록했다.

현재 가설은 ‘목욕 관련 링크·스크린샷을 공유하면, 장소·제품·팁으로 자동 정리되어 필요할 때 다시 찾는 개인 보관함’이다. 이미 출시한 ‘씻고 쉬는 아카이브’와 연결하되, 운영자가 모든 시설 정책과 제품 정보를 취재하는 모델로 되돌아가지 않는 것이 조건이다.

결론: 참고할 사례가 충분하다. 특히 Stasht는 장소와 제품을 함께 다루는 직접적인 기능 비교 대상이고, mymind는 수동 분류를 줄이는 방식, ReciMe는 특정 분야의 정보로 변환하는 방식, 위시버킷은 제품 저장 이후의 쓰임을 보여준다. ‘목욕 전용’이라는 범위만으로 경쟁 우위가 생기지는 않는다. 목욕 콘텐츠를 따로 모을 만큼 저장량과 재탐색 필요가 있는지, 범용 앱보다 적은 수고로 다시 찾을 수 있는지가 미검증이다.

## 1. 주요 서비스 비교

### Stasht — 가장 가까운 범용 경쟁자

- 입력: 소셜 게시물·영상 링크, 웹 링크, 스크린샷. 공식 설명은 Instagram, TikTok, YouTube 등을 포함한다.
- 구성: 저장물, 추출한 장소·제품·이벤트·레시피, 지도, 검색, 알림. 공식 사이트에는 스파와 온천 관련 저장 예시도 있다.
- 자동화: 콘텐츠에서 대상을 추출하고 검색 가능한 카드로 바꾼다고 안내한다. 범위와 실제 인식률은 직접 시험이 필요하다.
- 이용 사례: App Store의 7월 31일 후기는 선물 아이디어·이벤트·식당·업무 자료를 함께 모으며, 3월 13일 후기는 나중에 선물을 고를 때 과거 발견을 다시 찾는 용도를 설명한다.
- 정리 부담: 8월 8일 후기는 TikTok 장소 저장을 긍정적으로 평가하면서도 컬렉션의 목적을 이해하기 어렵고 장소가 자동으로 묶이면 좋겠다고 요청한다.
- 의미: 대상 추출과 컬렉션 자동 구성은 다른 문제다. 여러 종류의 콘텐츠를 담는 것 자체는 바스타임만의 차별점이 아니다.

출처: [공식 소개](https://stasht.app/), [App Store 기능·이용 후기·업데이트](https://apps.apple.com/us/app/stasht-app-saves-that-work/id6756032175).

### Mapstr — 장소로 바꾸고 지도에서 다시 찾기

- 입력: Instagram·TikTok·웹 문서를 공유해 장소 후보를 추출한다. 사용자는 원하는 후보를 골라 추가한다.
- 구성: 계정당 하나의 개인 지도, 리스트 보기, 태그, 방문 전후 상태, 메모·사진, 다른 사람의 지도.
- 자동화: 이미 쓰는 태그 중 적합한 태그를 제안한다. ‘폴더를 전혀 생각하지 않아도 되는 완전 자동 정리’와는 구분해야 한다.
- 이용 사례: 2023-05-06 App Store 후기는 쉬는 날 주변을 탐색하거나, 저장한 장소 근처에 갔을 때 들르는 용도를 설명한다.
- 의미: 사용자는 저장 화면보다 ‘어느 지역에 갔을 때 다시 꺼내는 화면’에서 가치를 얻을 수 있다. 목욕 제품을 담는 기능의 근거는 아니다.

출처: [소셜 공유 흐름](https://en.mapstr.com/fonctionnalites/ne-perdez-plus-les-bonnes-adresses-reperees-en-ligne), [지도·태그 구조 FAQ](https://en.mapstr.com/faq), [미국 App Store 후기](https://apps.apple.com/us/app/mapstr-save-follow-places/id917288465).

### mymind — 정리하지 않는 사람을 위한 검색 중심 보관함

- 입력: 이미지, 스크린샷, 링크, 기사, 제품 페이지, 메모.
- 구성: 전체 저장물, 검색, Smart Spaces, 과거 저장물을 다시 보는 기능.
- 자동화: 이미지 태깅·문자 인식·링크 종류 분류를 안내한다. Smart Spaces는 검색 조건을 저장해 해당 조건에 맞는 새 저장물이 자동으로 포함되는 방식이다. 원하는 컬렉션 이름을 모두 스스로 만들어주는 기능이라고 이해하면 부정확하다.
- 이용 사례: 인도 App Store의 2025-03-09 후기는 그래픽 디자인 영감을 모으는 용도를 언급한다. 영국의 2024-08-10 후기는 외부에서 접속이 불안정할 때 접근하기 어렵고 검색어가 기대대로 잡히지 않았던 경험을 설명한다. 후자는 과거 버전 경험이다.
- 의미: 저장 단계에서 폴더를 묻지 않고, 기억나는 단서로 다시 찾는 방식이 핵심 참고점이다.

출처: [공식 소개](https://mymind.com/), [Smart Spaces 구조](https://mymind.com/how-to-get-the-most-out-of-spaces), [현재 도움말의 검색 조건 설명](https://mymind.helpscoutdocs.com/article/70-tips-for-using-smart-spaces), [인도 후기](https://apps.apple.com/in/app/mymind-extend-your-mind/id1520332347?platform=iphone&see-all=reviews), [영국 후기](https://apps.apple.com/gb/app/mymind-extend-your-mind/id1520332347?platform=ipad&see-all=reviews).

### ReciMe — 분야 특화가 실용성으로 연결되는 사례

- 입력: 소셜 영상·게시물, 웹 레시피, 사진·기존 기록.
- 구성: 재료와 조리 순서로 정리한 레시피 카드, 요리책 묶음, 식단 계획, 장보기 목록.
- 자동화: 재료·순서 추출과 장보기 목록 생성. 주제별 요리책은 사용자가 만드는 구조도 포함한다. 가져오기 자동화가 전체 분류 자동화를 뜻하지 않는다.
- 이용 사례: 2025-10-02 App Store 후기는 여러 곳에 흩어진 레시피를 실제 조리에 쓸 수 있는 형식으로 바꾼 점과 원본 링크 보존을 높이 평가한다. 2025-01-04 후기는 저장한 레시피를 식단에 넣고 장보기 목록을 활용한다.
- 불편: 2026-02-16 Google Play 후기는 이름이나 넣어둔 요리책을 기억하지 못해 최근 저장물을 찾기 어렵다고 설명한다. 2026-09-05 후기는 로그인과 로딩 문제를 보고한다.
- 의미: 특화의 가치는 전문 분야 이름보다 저장물에서 뽑아주는 정보와 다음 행동에 있다. 바스타임은 원본에서 확인 가능한 장소·제품 정보를 뽑아 지도나 판매 페이지로 연결하는 정도부터 검증할 수 있다.

- 의미: 저장 후에는 ‘사고 싶은 것’과 ‘이미 산 것’이 갈라진다. 실시간 가격·재고를 약속하면 추가적인 정확성·운영 부담이 생긴다.

- 이번 조사에서 위 기능과 같은 범위의 독립 이용 후기 분석은 하지 않았다. 공식 구조의 참고 사례로만 사용한다.

## 2. 경쟁을 해석할 때 주의할 점

### 추가 확인: C멤버십 사용자 제공 화면

조사 후 사용자가 제공한 C멤버십 화면에서 Instagram 작성자 표시, 콘텐츠 요약, 지도, 연결된 장소 5개, 장소별 주소·평점·평가 수, 원문, 콘텐츠 추가 버튼을 확인했다. 앞서 공식 앱스토어 설명만으로 확인하지 못했던 소셜 콘텐츠 정리 화면이 실제로 존재한다는 시각적 근거다. 사용자는 앱 안에서 릴스가 재생된다고 설명했다. 재생 방식은 정지 화면으로 확인할 수 없다.

원문에 상호·위치·영업시간·추천 내용이 이미 있어 캡션 추출·요약과 지도 장소 매칭만으로 상당 부분을 구성할 수 있다. 영상 전체를 분석했는지, 수동으로 편집했는지, 사전 처리했는지, 최초 요청 때 처리한 뒤 재사용하는지는 미확인이다. 폴더 저장 과정도 첨부 화면에는 보이지 않는다. Google Places API는 주소·사진·평점·평가 수 같은 필드를 제공하지만 C멤버십이 실제로 그 API를 사용한다는 증거는 아니다. [공식 Places 필드 설명](https://developers.google.com/maps/documentation/places/web-service/reference/rest/v1/places).

제품 구성의 참고점은 ‘게시물 한 개에 장소 여러 개’라는 관계와, 원본 콘텐츠 보관 및 개별 장소 저장을 구분하는 방식이다. 바스타임에서도 한 콘텐츠의 여러 제품·장소를 선택적으로 챙길 수 있어야 한다는 후속 가설이 생겼다.

‘자동 정리’는 적어도 네 단계다.

1. 캡처: 공유한 원본을 잃지 않고 담는다.
2. 추출: 장소명·제품명·지역 등 내용을 읽는다.
3. 분류: 장소·제품·팁, 지역·종류 같은 묶음에 넣는다.
4. 재탐색: 사용자가 기억하는 단서로 다시 꺼내고 다음 행동으로 연결한다.

Mapstr는 장소 추출과 기존 태그 제안을, ReciMe는 조리 정보 추출을, mymind는 검색 조건에 따라 갱신되는 묶음을 안내한다. 모두 같은 자동화가 아니다. Stasht의 컬렉션 관련 후기는 이 차이가 사용자에게도 중요함을 보여주는 개별 사례다.

이번 한국어·영어·일본어 검색에서는 ‘목욕 소셜 콘텐츠 + 제품 + 자동 보관’의 조합을 명확히 내세우는 직접 전문 경쟁자를 확인하지 못했다. 이는 부재의 증명도, 시장 기회의 크기에 대한 증명도 아니다. 범용 앱 안에서 목욕 카테고리를 만드는 것이 강력한 대안이다.

수요에 대해서는 저장 도구를 실제 사용하는 사례를 확인했다. 목욕 분야의 월간 활성 이용자, 지불 의향, 재방문율, 운영 수익성은 이번 자료로 추정하지 않는다. 특히 앱스토어 평점과 누적 다운로드를 유지율로 읽지 않는다.

## 3. 바스타임에 대한 제안 — 조사에서 도출한 가설

### 한 문장 약속

‘목욕하다 발견한 것’보다 ‘보다가 발견한 목욕’을 담는 도구:

**온천도, 입욕제도. 공유해두면 알아서 모여 있고, 필요할 때 다시 찾는 바스타임.**

### 정보 구성

하나의 보관함에 들어오되, 대상에 맞는 정보와 다음 행동을 보여준다. 플랫폼 이름은 출처로 남기고, 기본 탐색을 Instagram 폴더·YouTube 폴더로 나누지 않는다.

| 대상 | 우선 추출할 정보 | 자동 모음 예시 | 다시 열었을 때 할 일 |
|---|---|---|---|
| 장소 | 이름, 국가·도시, 시설 종류, 원본 링크 | 후쿠오카, 온천, 사우나 | 원본 보기, 지도 열기 |
| 제품 | 브랜드·제품명, 제품 종류, 확인 가능한 판매 링크 | 입욕제, 타월, 욕조 용품 | 원본 보기, 판매 페이지 열기 |
| 팁·아이디어 | 짧은 주제, 원문에 있는 단서, 원본 링크 | 욕조 관리, 목욕 준비 | 원본 다시 보기 |
| 대상 불명 | 원본과 확보 가능한 제목·미리보기 | 최근 담은 것 | 그대로 열기, 선택적 수정 |

위 표는 구현 완료 기능이 아니다. 향·거품·야간 이용 같은 세부 태그는 원문에 근거가 있을 때만 붙인다. 소개 영상의 과거 정보와 현재 시설 정책을 혼동하지 않도록 출처와 저장 시점을 남긴다. 제품의 효능이나 피부 적합성은 추측하지 않는다.

### 수고를 줄이는 화면

- 공유하면 먼저 저장 완료. 이름·지역·카테고리 입력 폼을 기본 관문으로 두지 않는다.
- 첫 화면은 최근 담은 것과 검색. 장소·제품·팁은 자동 필터로 제공한다.
- 지역과 제품 종류별 모음은 저장 내용이 생길 때 나타난다. 빈 폴더를 먼저 만들게 하지 않는다.
- 한 항목이 ‘후쿠오카’와 ‘온천’에 동시에 보일 수 있다. 사용자가 저장 위치 하나를 골라야 하지 않게 한다.
- 분석이 안 되어도 실패한 숙제 목록을 만들지 않는다. 원본은 보관하고 나중에 수정할 수 있게 한다.
- 이름이 모호하면 지점을 임의로 확정하거나 비슷한 제품을 강제로 합치지 않는다. 후보 확인은 필요한 때에만 요청한다.
- 상세 화면에서 같은 대상에 관한 여러 원본을 함께 본다. 중복 링크와 같은 대상의 다른 콘텐츠는 구분한다.
- ‘가고 싶음/다녀옴’, ‘사고 싶음/샀음’은 선택 사항으로 작게 제공한다. 평가·후기 작성은 필수가 아니다.

### 기존 프로토타입에서 바꿔볼 부분

현재 프로토타입은 장소 중심이고, 링크 저장 시 이름·지역 입력 폼을 보여준다. 다음 실험에서는 제품·팁 카드를 추가하고 기본 입력 과정을 줄여야 한다. ‘정리 대기’가 계속 쌓이는 모습보다, 분류되지 않은 원본도 정상적으로 검색·재생 가능한 상태를 검증해야 한다.

이 보고서 작성 중 프로토타입 코드는 수정하지 않았다. 실제 영상 분석과 공유 메뉴 연동은 여전히 미구현이다.

## 4. 작게 비교해볼 실사용 실험

### 직접 써볼 순서

1. Stasht: 바스타임 없이도 목욕 장소·제품을 함께 담기에 충분한지 확인한다.
2. mymind: 폴더를 만들지 않고 저장한 다음, 불완전한 기억으로 찾을 수 있는지 본다.
3. Mapstr: 장소 후보 선택부터 지도에서 다시 찾기까지의 편의성을 비교한다.
4. 위시버킷: 국내 상품 링크에서 이미지·이름이 얼마나 잘 들어오고 구매 전후 상태가 어떻게 보이는지 확인한다.
5. ReciMe: 관심 있는 레시피 몇 개로 특화 카드가 일반 북마크보다 어디서 유용해지는지 경험한다. 목욕 링크를 억지로 시험하지 않는다.

가입·구독을 대신 진행하지 않았다. 요금과 무료 범위는 실제 가입 화면에서 다시 확인한다. ReciMe는 공식 도움말에서 주 5개 무료 가져오기를 안내한다. mymind는 구독 요금제를 안내한다. 가격을 근거로 수익성을 추정하지 않는다. [ReciMe 무료 범위](https://recime.app/help/en/articles/11596201-is-there-a-free-version-of-the-app), [mymind 요금](https://access.mymind.com/pricing).

### 공통 입력 세트

의도적으로 예쁜 예시만 고르지 않는다. 실제로 저장하고 싶은 20개를 사용한다.

- 장소 8개: 한국·일본, 여러 플랫폼, 복수 시설을 소개한 콘텐츠, 같은 장소의 다른 영상 포함.
- 제품 8개: 상품 페이지, 제품 소개 영상, 브랜드나 제품명을 알기 어려운 사례, 같은 제품의 다른 판매처 포함.
- 목욕 팁 4개: 청소·준비·사용법 등 실제 다시 볼 이유가 있는 콘텐츠.

각 앱의 지원 범위에 맞는 항목만 시험하며 미지원은 실패율에 섞지 않는다. 기존 Instagram·YouTube 저장과 카카오톡 나에게 보내기 등 평소 방식도 비교 대상으로 둔다.

### 측정할 것

| 시점 | 관찰 항목 |
|---|---|
| 저장 직후 | 탭 수, 글자 입력 요구, 원본 보존, 처리 시간 |
| 정리 후 | 대분류·지역·제품명 정확성, 잘못 합쳐진 대상, 직접 고치는 수고 |
| 2~3일 후 | 정확한 제목을 모른 채 특정 저장물 5개를 찾아보는 성공 수·시간 |
| 1~2주 후 | 재방문, 원본·지도·판매처 열기, 평소 저장 방식으로 돌아간 이유 |

시간과 성공률 목표는 실제 기준값을 본 뒤 정한다. 적은 표본의 결과를 시장 전체 수요로 일반화하지 않는다. 초기에는 목욕 콘텐츠를 이미 저장하는 사람과, 보기만 하고 저장하지 않는 사람을 구분해 관찰한다.

### 진행 판단

- 계속할 근거: 폴더를 만들지 않아도 원하는 것을 더 빨리 찾고, 이후에도 스스로 다시 공유해 저장한다.
- 수정할 근거: 저장은 늘지만 다시 찾기 어렵다. 카드 종류·검색 단서·다음 행동을 조정한다.
- 범위를 재검토할 근거: 범용 서비스에 목욕 태그 하나만 두어도 충분하거나, 목욕 저장 빈도가 별도 앱을 유지할 만큼 나오지 않는다.

## 5. 운영상 발견

소셜 연동은 출시 후에도 유지 작업이 필요하다. Stasht의 2026-07-12 변경 기록에는 Instagram 컬렉션 로딩 변경으로 기존 저장 가져오기를 수정했다는 설명이 있다. 이는 플랫폼 의존성의 실제 사례이지, 모든 연동이 불가능하다는 뜻은 아니다. [Stasht 변경 기록](https://apps.apple.com/us/app/stasht-app-saves-that-work/id6756032175).

첫 실험에서 검증할 것은 ‘아무 영상이나 완벽하게 이해한다’는 약속이 아니라, 실제 사용자가 가져오는 목욕 콘텐츠에서 수동 정리 시간을 줄일 수 있는지다. 시설 정책·실시간 가격·재고 추적까지 동시에 맡으면 이전 가이드 모델과 비슷한 유지 부담을 다시 가져올 수 있다.
