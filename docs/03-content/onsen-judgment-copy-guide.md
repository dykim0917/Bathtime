# 바스타임 판정문 작성 규칙

후기 데이터를 바스타임의 판정문으로 옮길 때 지키는 원칙과 문체 규칙입니다. 상세 페이지의 `바스타임 판정`, `이용 경험 분석`, `판정 근거` 영역을 비롯해 후기 집계를 근거로 서술하는 모든 카피에 적용합니다.

용어 표기는 [온천 용어 가이드](./onsen-term-guide.md)를 따릅니다.

## 1. 포지션 선언: 우리는 인용하지 않고 판정한다

후기를 다루는 방식에는 세 단계가 있습니다.

1. 원문 인용/재게시: 남의 콘텐츠를 옮기는 것. 저작권 문제와 파쿠리 인상을 만듭니다. 금지합니다.
2. 전달: `후기에 이렇게 나와 있다`는 화법. 가치가 남의 글에 있고 바스타임은 배달만 하는 포지션입니다. 금지합니다.
3. 판정: 읽고, 세고, 분류한 뒤 바스타임의 이름으로 결론을 내리는 것. 원문은 근거이고 분석이 상품입니다. 바스타임의 방식은 3번뿐입니다.

대원칙은 다음과 같습니다.

> 후기의 문장과 말투는 드러내지 않는다. 하지만 바스타임이 읽고 집계한 규모와 출처 메타는 숨기지 않는다.

즉, 후기 원문과 의역은 사용자에게 노출하지 않습니다. 대신 직접 읽은 규모, 온천 관련 건수, 확인 플랫폼, 긍정/부정 집계처럼 바스타임이 만든 분석 결과는 명시합니다. 수치와 출처 메타를 숨기면 판정은 근거 없는 큐레이션처럼 보입니다.

## 2. 출처 노출 규칙

### 금지

- 후기 원문 인용
- 후기 원문을 문장만 바꾼 의역 인용
- `후기에 따르면`, `리뷰에서 말하길`, `여러 후기가 말하길` 같은 전달자 화법
- `자란 리뷰에서 이런 말이 많습니다`처럼 플랫폼을 후기 내용의 주어로 쓰는 문장
- 사용자 노출 카피에서 `후기 신호`, `신호가 강하다`, `신호가 있다` 같은 내부 분석어를 쓰는 것

### 허용

- `직접 읽은 이용 경험 342건`
- `온천 관련 234건`
- `확인 플랫폼 4개`
- `자란, 라쿠텐, 구글 지도, 트립어드바이저`
- `온천 관련 234건 중 객실 노천탕 언급 86건, 부정 판정 3건`
- 출처 각주, 근거 메타 정보, 관리자용 내부 필드

플랫폼 실명은 후기 내용을 전달하기 위해 쓰는 것이 아니라, 바스타임 판정의 검증 가능성을 보이기 위해 씁니다.
플랫폼명은 [온천 용어 가이드](./onsen-term-guide.md)의 UI 라벨을 따릅니다.

## 3. 사용자 노출 용어

사용자에게 보이는 영역에서는 `신호`라는 말을 쓰지 않습니다. `신호`는 내부 분석과 태깅을 위한 말이고, 일반 사용자의 선택 문맥에서는 어색하게 읽힙니다.

| 내부 표현 | 사용자 노출 표현 |
| --- | --- |
| 후기 신호 | 판정 근거 / 이용 경험 분석 |
| 신호 1 | 근거 1 / 확인 포인트 1 |
| 강한 신호 | 확인됨 / 뚜렷함 |
| 약한 신호 | 추가 확인 필요 / 정보 부족 |
| 물성 신호 | 수질 확인 |
| 주의 신호 | 미리 볼 점 |
| 신호 필터 | 확인 포인트 / 온천 기준 |

내부 리서치 파일, 스크립트 변수명, DB 원천 필드에서는 `signal`을 유지할 수 있습니다. 단, 화면 문구, 발행 카피, 관리자 입력 가이드, 사용자용 설명에는 쓰지 않습니다.

## 4. 섹션 구조 템플릿

판정문 섹션은 아래 순서를 따릅니다.

```text
수집 브리핑 · 직접 읽은 이용 경험 N건 · 온천 관련 N건 · 확인 플랫폼 N개(플랫폼 실명 표기)

바스타임 판정
[숙소 전체를 한 문장으로 요약하는 헤드라인 판정]

근거 1 — [헤드라인: 단정형 한 문장]
[집계: 관련 언급 N건, 부정 판정 N건 등 숫자 서술]
[해석: 반복되는 조건, 구조적 원인, 선택 의미]
결론: [유저가 취할 행동 또는 결론]

근거 2 — (같은 구조 반복)
근거 3 — (같은 구조 반복)
```

- 근거 개수는 3~5개를 권장합니다.
- 숫자로 채울 수 없는 항목은 개수를 줄이는 한이 있어도 싣지 않습니다.
- 배치 순서는 `긍정 확정 판정` → `조건부 판정` → `소수 반복 판정`입니다.
- 수집 브리핑은 반드시 판정보다 먼저 노출합니다. 브리핑 없는 판정은 근거 없는 주장으로 읽힙니다.

## 5. 숫자 규칙

### 1. 카운트 없는 판정은 싣지 않는다

`많더라`, `종종 보인다`, `대체로` 같은 무숫자 빈도 표현은 쓰지 않습니다. 숫자가 있으면 판정이고, 없으면 소문입니다.

### 2. 부정 판정도 함께 센다

좋은 이야기만 고르는 큐레이션과 전수를 읽고 분석한 판정의 차이는 부정값을 함께 세는 데서 나옵니다.

권장 형식:

```text
온천 관련 234건 중 객실 노천탕 언급 86건, 부정 판정 3건.
```

부정 판정이 0건이면 0건이라고 씁니다.

### 3. 분모를 밝힌다

`온천 관련 234건 중`처럼 어느 풀에서 센 숫자인지 명시합니다. 직접 읽은 풀과 플랫폼 노출 풀을 섞지 않습니다.

### 4. 플랫폼은 실명으로 쓴다

`플랫폼 4개`만 쓰지 말고 `자란, 라쿠텐, 구글 지도, 트립어드바이저`처럼 이름을 함께 둡니다. 실명이 검증 가능성을 만듭니다.

## 5-1. 판정 근거 채택 임계값

숫자가 있다는 이유만으로 모든 내부 태그를 판정 근거로 올리지 않습니다. `4건 / 1플랫폼`처럼 작고 한쪽 출처에 몰린 항목은 데이터에서 보이는 흔적일 수는 있지만, 바스타임의 판정 근거가 되기에는 약합니다.

`full` 판정 항목으로 채택하려면 v0.1 기준으로 아래 조건을 모두 충족해야 합니다.

- 직접 읽은 이용 경험 300건 이상
- 온천 관련 이용 경험 200건 이상
- 직접 본문 플랫폼 3개 이상
- 해당 판정 항목의 언급 수가 `10건 이상`이면서 동시에 `분모의 2% 이상`
- 해당 판정 항목이 `2개 이상 플랫폼`에서 확인됨
- 긍정/혼합/부정 방향 카운트가 분리되어 있음

분모는 해당 항목의 `counts.denominator`를 따릅니다. 보통 온천 경험 항목은 `onsen_related`, 예약/접근/운영 같은 전체 숙박 경험 항목은 `experiences_read`를 씁니다.

미달 항목은 다음처럼 처리합니다.

| 상태 | 기준 | 사용자 노출 |
| --- | --- | --- |
| 판정 근거 채택 | 10건 이상, 분모 2% 이상, 2플랫폼 이상 | `items[]`의 독립 근거로 사용 가능 |
| 확인해둘 점 | 5건 이상, 2플랫폼 이상이나 판정 근거 기준 미달 | 독립 근거로 세지 않고 보조 주의 문장까지만 허용 |
| 내부 참고 | 1~4건 또는 단일 플랫폼 | 사용자 노출 금지. 다음 조사/QA 메모로만 보존 |

단일 플랫폼 4건짜리 항목은 `내부 참고`입니다. 예를 들어 `유량 주의 4건 / 1플랫폼`은 full verdict의 근거 항목이 될 수 없고, 공식 운영 사실이 따로 확인되는 경우에만 예약 전 확인 문장으로 바꿀 수 있습니다. 이때도 후기 기반 판정처럼 쓰지 않습니다.

이 임계값은 v0.1입니다. `하치요`, `마루가미야`, `콘자쿠안` 3개 full verdict 파일럿을 작성한 뒤 조정할 수 있지만, 조정 전에는 이 기준을 모든 작업자에게 동일하게 적용합니다.

## 5-2. 태그 방향성 규칙

`객실 노천탕 127건`은 언급 수이지 자동으로 만족 수가 아닙니다. 판정문에 쓰는 모든 주요 항목은 방향을 함께 가져야 합니다.

원천 데이터의 각 직접 리뷰 행은 아래 중 하나의 방향을 가져야 합니다.

| direction | 의미 | verdict 반영 |
| --- | --- | --- |
| `positive` | 해당 욕장/수질/운영 경험에 대한 긍정 평가 | `mentions`에 포함 |
| `mixed` | 장점과 조건, 만족과 주의가 함께 있음 | `mentions`에 포함, 해석 문장에서 조건부로 다룸 |
| `negative` | 불만, 결함, 불편, 기대 불일치 | `mentions`와 `negative`에 포함 |
| `neutral` | 단순 언급, 객실명/플랜명, 시설 존재 확인 | 기본적으로 `mentions`에서 제외 |

`items[].counts.mentions`는 기본적으로 `positive + mixed + negative`입니다. `neutral`은 공식/시설 사실 또는 bath-area confidence에는 쓸 수 있지만, 만족/불만 판정의 언급 수에는 넣지 않습니다.

`items[].counts.negative`는 `negative`만 셉니다. `mixed`는 별도 `direction_counts.mixed`로 남기고, 본문에서 조건부 해석으로 처리합니다.

full verdict 변환의 단일 근거는 다음 순서로 둡니다.

1. `verdict_candidate_items_*.json`이 있으면 이를 canonical 집계로 사용합니다.
2. 없으면 `direct_review_sample_index_*.csv`에서 `platform`, `bath_area`, `signal_type` 또는 `signal_tags`, `signal_direction`을 재집계합니다.
3. `review_signal_summary_*.md/json`은 사람이 읽는 요약입니다. canonical 집계가 없을 때 검산 보조로만 씁니다.
4. `collection_stats_*.json`은 숙소 전체 표본 규모 확인용입니다. 개별 판정 항목의 방향 카운트 원천으로 쓰지 않습니다.

요약 문서마다 표기 방식이 다를 수 있으므로, full verdict를 만들 때는 `mentions`, `negative`, `direction_counts`, `platform_count`, `denominator`를 변환 산출물에 명시해야 합니다.

## 5-3. 다국어 확장 규칙

판정 모델의 카운트와 구조화 팩트는 언어 중립으로 유지합니다. `water_source_type`, `bath_scope`, `briefing`, `items[].counts`, `fact_statuses`는 한국어와 영어가 함께 참조하는 공통 기준입니다.

언어별로 달라지는 것은 문장 레이어입니다. 영어권 파일럿처럼 다른 시장을 대상으로 할 때는 `localized_copy.en` 같은 locale별 오버레이에 문장을 둡니다. 기존 한국어 판정문을 직접 덮어쓰지 않습니다.

다국어 문장에도 같은 원칙을 적용합니다.

- 원문 이용 경험 인용 금지
- 의역 인용 금지
- 카운트 없는 판정 금지
- 시장별 용어 가이드 없는 직역 금지

한국어의 `직수 온천`은 영어로 그대로 직역하지 않습니다. 용어는 [온천 용어 가이드](./onsen-term-guide.md)의 시장별 용어 가이드 원칙을 따릅니다.

## 6. 경어 규칙

기본 문체는 `합니다체`입니다. 반말 평어체는 UI 안에서 고압적으로 읽히고, `해요체`는 판정의 힘이 빠져 블로그 후기 톤이 됩니다.

### 1. 사실 서술과 행동 권유의 경어 수위를 분리한다

- 집계와 판정 근거: 사실 서술형 합니다체를 씁니다. 예: `일관됩니다`, `확인됐습니다`
- 유저 행동 권유: 상대 높임을 허용합니다. 예: `확인하시기 바랍니다`, `고민하지 않으셔도 됩니다`

### 2. 헤드라인의 단정은 유지한다

어미만 높이고 주장 강도는 유지합니다.

허용:

```text
겨울 수온은 이 숙소의 유일한 조건부입니다.
```

금지:

```text
겨울 수온은 조건부일 수 있습니다.
겨울 수온은 확인되는 편입니다.
```

데이터가 불충분한 항목은 약하게 쓰는 대신 판정 자체를 싣지 않습니다.

### 3. 집계 나열 구간은 개조식 종결을 허용한다

`언급 N건, 부정 판정 N건.`처럼 짧게 끝낼 수 있습니다. 나열까지 모두 문장으로 풀면 리듬이 죽습니다.

### 4. UI 라벨, 배지, 칩은 경어 예외다

초단문 자리는 명사형으로 씁니다. 경어체는 문장 단위에만 적용합니다.

## 7. 금지 목록

- 후기 원문 인용
- 후기 원문을 사실상 옮긴 의역 인용
- `후기에 따르면`, `리뷰에서`, `여러 후기가` 같은 전달자 화법
- 사용자 노출 문구에서 `신호`, `후기 신호`, `신호가 강하다`
- 숫자 없는 빈도 표현: `많더라`, `종종`, `대체로`, `~인 듯`
- 판정 문장의 헤지: `~인 편입니다`, `~일 수 있습니다`, `~로 보입니다`
- 근거 수치 없는 판정 문장

## 8. 표준 예시

```text
수집 브리핑 · 직접 읽은 이용 경험 342건 · 온천 관련 234건 · 확인 플랫폼 4개(자란, 라쿠텐, 구글 지도, 트립어드바이저)

바스타임 판정
객실 안에서 온천이 완결되는 숙소입니다. 대신 수온은 계절을 탑니다.

근거 1 — 객실 노천탕 만족은 논쟁이 없는 항목입니다.
온천 관련 234건 중 객실 노천탕 언급 86건, 부정 판정 3건. 프라이버시와 독립성에 대한 평가는 플랫폼을 가리지 않고 일관됩니다.
결론: 대욕장 없이 객실탕만으로 충분한지 고민하지 않으셔도 되는 구조입니다.

근거 2 — 겨울 수온은 이 숙소의 유일한 조건부입니다.
11~3월 이용 경험 중 노천탕 냉감 지적 14건. 직수 방식의 구조적 특성으로, 결함이 아니라 계절 조건입니다.
결론: 겨울 예약이라면 가온 가능 여부를 예약 단계에서 확인하시기 바랍니다.

근거 3 — 여름철 벌레 유입은 소수지만 반복되는 변수입니다.
6~9월 이용 경험 중 벌레 유입 관련 부정 판정 7건. 전 객실 노천 구조에서 생기는 공통 변수입니다.
결론: 민감하신 분은 여름을 피하시고, 가신다면 감수 가능한 범위입니다.
```
