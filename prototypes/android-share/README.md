# 바스타임 Android 공유 테스트

릴스·쇼츠 등을 보다가 링크 하나를 담고 원래 화면으로 돌아가는 사용성을 확인하는 작은 네이티브 Android 앱이다. 기존 Expo 앱에 합치기 전의 독립 실험이며, 웹 보관함 프로토타입과 저장소를 공유하지 않는다.

- 앱 이름: **바스타임 테스트**
- 공유 대상 이름: **바스타임에 담기**
- 패키지: `com.bathtimestudio.bathtime.pockettest` — 기존 바스타임과 함께 설치 가능
- Android 8.0 이상, 테스트용 debug 서명
- 서버·계정·AI API·네트워크 권한 없음

## 폰에서 해보기

1. `output/bathtime-share/bathtime-share-test.apk`를 폰으로 옮겨 설치한다. Android가 요청하면 해당 파일을 여는 앱의 설치 허용을 켠다.
2. Instagram 릴스 또는 YouTube 쇼츠의 **공유 → 더보기/다른 앱 → 바스타임에 담기**를 선택한다. 메뉴 이름과 단계는 원본 앱 버전에 따라 다르다.
3. 링크를 즉시 로컬 저장하고 작은 확인창을 표시한다. 성공 시 약 1.6초 후 닫힌다. `보던 화면으로`를 눌러 바로 닫아도 된다. 접근성 설정에 따라 표시 시간이 늘어나며, 화면 읽기 기능 사용 시 직접 닫는다.
4. 나중에 **바스타임 테스트**를 열면 링크 목록이 보인다. 누르면 원문을 열고, 길게 누르면 삭제할 수 있다.

가장 먼저 확인할 것:

- 공유 메뉴에서 바스타임을 찾기가 번거롭지 않은가?
- 확인창이 너무 길거나 짧게 뜨지 않는가?
- 원래 릴스·쇼츠로 돌아오는가? 재생 위치를 유지하는가? 재생이 멈췄다면 직접 다시 재생해야 하는가?
- 같은 링크를 다시 공유해도 한 개만 남는가?
- 비행기 모드에서도 저장되고 앱을 종료했다 열어도 남아 있는가?
- 지도 링크와 상품 링크도 담을 수 있는가?

## 현재 동작과 한계

`ACTION_SEND`의 `text/plain`을 수신한다. `EXTRA_TEXT`를 먼저 읽고 텍스트나 HTTP(S) 주소가 있는 `ClipData`를 보조로 처리한다. 여러 URL이 포함되면 첫 번째 유효한 URL을 대표로 쓰고, 전달받은 텍스트 전체도 로컬에 보관한다. 앱이 공유하지 않은 캡션·썸네일·영상은 가져오지 않는다.

저장 데이터는 원본 URL, 공유 텍스트, 전달받은 제목, 저장 시각, 중복 비교 키다. Instagram의 일부 공유 추적값과 YouTube의 Shorts/watch/youtu.be 형식을 중복 비교에 반영한다. Google Maps 단축 링크를 펼치거나 서로 다른 상품 URL을 같은 제품으로 묶는 작업은 하지 않는다.

로컬 파일 기록이 성공한 뒤에만 저장 완료를 표시한다. 링크 없는 입력과 저장 실패는 오류 안내를 보여주며 자동으로 닫지 않는다. 원래 앱의 영상 재생 상태는 그 앱의 동작에 달려 있으므로 실제 폰에서 확인해야 한다.

앱 삭제 시 저장 데이터도 삭제된다. 자동 정리, 서버 업로드, 데이터 이전은 구현하지 않았다.

## 빌드

JDK 17과 Android SDK Platform 36이 필요하다. `JAVA_HOME`, `ANDROID_HOME`을 설치 경로에 맞게 설정한 뒤 이 폴더에서 실행한다.

```powershell
.\gradlew.bat --no-daemon testDebugUnitTest lintDebug assembleDebug
```

산출물: `build/outputs/apk/debug/BathtimeSharePrototype-debug.apk`

## 2026-09-21 검증

- Debug APK 빌드 성공.
- 링크 추출, 잘못된 입력, 중복 비교에 대한 JUnit 테스트 3개 통과.
- Android lint 오류 0개. 구버전 백업 설정에 대한 경고 1개가 보고된다. manifest에서 백업을 비활성화했다.
- 별도 Android 15 에뮬레이터에 APK 설치 및 빈 보관함 실행 확인.
- 링크 없이 공유 Activity를 연 경우 오류 확인창을 표시하고, 버튼으로 이전 화면에 복귀하는 것 확인.
- 해당 실행에서 AndroidRuntime 오류 없음.
- 실제 공유 입력을 주입하는 `ACTION_SEND` 명령은 자동 승인 검토에서 차단됐다. 테스트 앱만 지정한 호출도 차단됐고 구체적인 사유는 제공되지 않았다. 따라서 **정상 공유 → 실제 저장 → 자동 복귀와 재실행 후 보존은 에뮬레이터에서 종단 검증하지 못했다.** 폰의 Instagram/YouTube 공유 메뉴에서 확인해야 한다.

### 사용자 실기기 테스트 결과

사용자가 이후 전달한 화면과 설명에서 YouTube Shorts 1개, Instagram 게시물 2개의 저장을 확인했다. 두 앱 위에 저장 완료 확인창이 표시됐고, 보관함에는 링크 3개가 나타났다. 사용자는 바스타임 선택 이후의 동선이 깔끔하고 저장이 잘 된다고 평가했다. 앱 재시작 후 보존, 오프라인 저장, 중복 처리의 실기기 결과는 별도로 보고되지 않았다.

- 남은 불편은 공유 대상 선택 전 단계다. YouTube에서는 첫 공유 메뉴의 앱 행을 끝까지 이동해 `더보기`를 누른 뒤 바스타임을 찾아야 했다. Instagram에서는 종이비행기 메뉴에서 다시 `공유하기`를 눌러야 했다.
- 이번 입력에서 YouTube 제목은 카드에 표시됐지만 Instagram 두 건은 제목 없이 URL만 표시됐다. 모든 게시물에서 동일하다고 일반화하지 않는다.
- Android 시스템 공유창의 대상 등록·추천과 원본 앱이 직접 만드는 공유 메뉴는 구분한다. 현재 APK는 `ACTION_SEND`/`text/plain`을 등록하고 있다. YouTube 첫 앱 행에 위치를 지정하는 공개 API는 이번 조사에서 확인하지 못했다. [Android 공유 문서](https://developer.android.com/develop/ui/compose/sharing/send), [Direct Share 문서](https://developer.android.com/develop/ui/compose/sharing/direct-share-targets)
- 사용자 사진의 YouTube 첫 공유 메뉴에는 Instagram `메시지`가 있다. 향후 DM 수신 기능을 구현하면 `쇼츠 공유 → Instagram 메시지 → 바스타임 계정`도 비교할 후보 경로다. 외부 YouTube 링크 수신과 원래 영상으로의 복귀는 아직 시험하지 않았다.

## 이후 서버를 붙일 때

사용자는 먼저 링크를 저장하고 나간다. 서버 대기열에 모인 링크를 운영자가 Codex로 정리하고, 출처와 결과를 확인해 반영하는 소규모 운영으로 시작할 수 있다. 이 대화가 서버 요청을 자동 수신하는 것은 아니므로 대기열 조회와 결과 반영 절차를 따로 연결해야 한다. 지금 APK에는 이 작업이 들어 있지 않다.

ChatGPT로 로그인한 Codex 사용은 구독 범위와 사용 한도를 따르며 API 키 사용과 과금 방식이 다르다. 구독을 무제한 API처럼 가정하지 않는다. 공식 문서는 [인증](https://learn.chatgpt.com/docs/auth), [사용 한도](https://learn.chatgpt.com/docs/pricing), [비대화형 실행](https://learn.chatgpt.com/docs/non-interactive-mode)을 참고한다.

링크만으로 본문에 접근할 수 없는 콘텐츠는 정리가 실패할 수 있다. 사용자가 공유하지 않은 영상·캡션까지 항상 분석 가능하다고 약속하지 않고, 원본 링크 저장은 유지하는 방향이다.
